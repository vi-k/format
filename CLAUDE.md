# Инструкции для Claude Code

Это точка входа для новой сессии. Она намеренно короткая: всё содержимое
живёт в `docs/handoff.md`, и дублировать его здесь нельзя — две копии
разойдутся, как разошлись дизайн-документы с кодом (разбор L17).

## С чего начать

1. Прочитать `docs/handoff.md` целиком. Это живой документ, обновляется
   каждую сессию.
2. Открытые пункты — раздел `## Что открыто` в нём. Первый пункт списка
   и есть следующее дело, если пользователь не сказал иначе.
3. Реестр вердиктов по внешнему ревью —
   `docs/records/2026-08-05[5]-project-review.md`. Секция Low разобрана
   целиком; Medium — частично.

## Что нельзя пропустить

- **Проверки перед коммитом обязательны** — полный список команд в
  `docs/handoff.md`, раздел `## Как проверить всё`. Не «обычно я гоняю
  тесты», а весь список: node-прогон и архив ловят то, чего не ловит
  `dart test`.
- **«Нет performance GREEN — нет коммита».** Правку, заявленную как
  ускорение, без замера не коммитить; замер — минимум из 25–40 раундов,
  A/B двух сборок подряд, никаких медиан. Если ускорение не
  подтвердилось, правка откатывается, а замер записывается.
- **Мержим прямо в `main`, без PR.** Проверки это не отменяет.
- **`docs/backlog.md` — файл владельца.** Не коммитить его правки вместе
  со своими: `git add -A ':(exclude)docs/backlog.md'`, и запускать `git
  add` из корня репозитория, иначе исключение разрешится не туда.
- **Документы проекта на русском**, код и комментарии в коде — на
  английском.
- **Отчёт ревью не редактируется молча.** У каждого пункта либо стоит
  вердикт, либо он открыт; удалять пункт нельзя.

## В конце сессии

Обновить `docs/handoff.md`: строку `Статус:` с датой, раздел про
сделанное и список открытого. Handoff, отставший от репозитория, — это
та же расходящаяся копия, о которой сказано выше.
