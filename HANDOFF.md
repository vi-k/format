## Что за проект

Dart-пакет форматирования: Python-подобные фигурные скобки (`{:...}`) и
printf-подобный диалект (`%...`) под одним движком.

- `lib/src/engine.dart` — библиотека-контейнер; почти всё остальное в
  `lib/src/` — её `part`-файлы (`format.dart`, `brace_parser.dart`,
  `format_spec.dart`, `number_format.dart`, `printf_*.dart`,
  `template_ir.dart`, `template_cache.dart`, `char_sink.dart`).
  Исключения — самостоятельные библиотеки: `binary64.dart`,
  `errors.dart`, `extensions.dart`, `number_locale.dart`, `text_unit.dart`,
  `double_format.dart`.
- `lib/format.dart` — публичный экспорт. Всё, чего в нём нет, — внутреннее.
- Шаблон компилируется в программу op'ов (IR) и пишется прямо в
  `CharSink`; рядом живёт **legacy-путь** (`debugFormatBraceWithoutIr`,
  `debugFormatPrintfWithoutIr`) — он несущий, см. ловушки.
- `benchmark/` — гейт производительности (`runner.dart`, `gates.dart`,
  `scenarios.dart`, эталон в `benchmark/results/`) и отдельный пакет
  `benchmark/suite/` со сравнительной матрицей.
- `docs/` — плоско, `YYYY-MM-DD[N]-name.md`. Источник истины по открытым
  вопросам — `docs/2026-08-05[5]-project-review.md`.

## Конвенции

- Документы, планы, спеки и этот файл — по-русски. Новые документы — в
  `docs/` по шаблону `YYYY-MM-DD[N]-name.md` (`-plan`, `-design`).
- `dart format` перед коммитом (локальный хук `.git/hooks/pre-commit`; в
  новом клоне ставится заново). **Репозиторий формат-чист целиком** —
  старое предупреждение из архива про 21 расходящийся файл больше не
  действует, `dart format .` можно и нужно запускать на всё дерево.
- Analyzer: ноль замечаний, включая info, на `lib test example tool`.
  В `benchmark/` есть унаследованные info — там CI гоняет `dart analyze`
  без `--fatal-infos`.
- Timing-assert'ов в обычных тестах нет и быть не должно; производительность
  меряется бенчмарками и гейтом.
- `benchmark/baselines/*` не трогать и не форматировать: `format20` —
  замороженная копия 2.0, `format16` в git не хранится и материализуется
  `benchmark/baselines/format16/fetch.dart` (обязательный шаг в новом
  клоне). `sprintf` запинен на `7.0.0` — бамп обнулит сопоставимость.
- Тестовые seam'ы (`debug*`) импортируются **только** через
  `package:format/src/engine.dart`.

## Как проверить всё

```sh
dart format . && dart analyze --fatal-infos lib test example tool
dart test                                    # 518 тестов
dart test -p node test/char_sink_test.dart test/template_ir_compile_test.dart \
  test/template_ir_diff_test.dart test/template_ir_fuzz_test.dart \
  test/js_number_dispatch_test.dart          # 75 тестов
dart test benchmark/test tool/test           # 32 теста, ~50 с
dart run tool/verify_package_archive.dart    # архив pub стоит сам по себе
(cd benchmark/suite && dart pub get && dart test)   # 15 тестов
(cd benchmark/suite && dart run bin/benchmark.dart) # матрица, ~60 с
```

Гейт производительности гоняется не на каждый PR, а по диспатчу:

```sh
gh workflow run ci.yaml --ref main
gh run download <id> -n performance-gate -D /tmp/gate
dart run benchmark/gates.dart --reports=/tmp/gate/jit-1.json,... \
  --record=$(date +%F) --output=benchmark/results/gate-baseline.json
```

Порядок и требования к отчётам — `benchmark/results/README.md`.

## Что открыто

Из отчёта (Medium):

- **M5** — кэш шаблонов ограничен числом записей, а не байтами: на
  длинных шаблонах амплификация памяти ×5.5.
- **M12** — сгенерированные артефакты (`python_format.json`,
  `python_identifier.dart`, `sprintf_common.json`) не сверяются с
  генераторами в CI; дрейфа сейчас нет, защиты от него нет.
- **M13** — CI не измеряет покрытие.
- **M18** — тройное дублирование числового layout'а и printf-обвязки.
- **M19** — веб-специфичный код брейсов не бенчмаркается вообще.
- **M20** — оверхед харнеса ~20 % и отсутствие защиты от DCE в
  `benchmark/runner.dart`.
- Секция Low целиком не разбиралась.

Отдельно, из работы над M17: **`{v:{w}d}`** (динамическая вложенная
спецификация) остаётся вне IR — она неизвестна на момент компиляции
программы. Ускорение требует кэша разобранной спецификации по
резолвленному тексту на узле; это самостоятельная работа.

Резервы производительности, не начатые:

- **dtoa прямо в sink** — double-op'ы сперва получают готовое тело строкой
  и только потом отдают его в sink; генерация цифр напрямую убрала бы
  промежуточную строку. Самый крупный оставшийся резерв.
- **Пул `CharSink`'ов** — сейчас sink создаётся на каждый вызов.

## Ловушки и знания

- **Двойная библиотека.** Смешение `package:format/...` и относительного
  `../lib/src/...` в одном файле создаёт две копии библиотеки с
  независимыми статиками и несовместимыми типами. Seam-тесты импортируют
  движок только через `package:format/src/engine.dart`.
- **Тесты кэша** обязаны звать `debugClearTemplateCaches` в `setUp`.
- **Legacy-путь не удалять.** `formatWithoutIr` — одновременно оракул
  parity-фаззера и baseline A/B-бенчмарка. Любое расширение IR (новый
  op, новая ветка классификатора) проверяется прогоном против него:
  так закрывались группировка (471 240 целочисленных случаев,
  1 797 120 double) и `n` (6 528 по четырём движкам). Матрицы в
  сокращённом виде живут в `test/template_ir_diff_test.dart` и гоняются
  и на VM, и на node.
- **Замеры: минимум, а не медиана.** При загрузке машины ≈4 медиана из
  15 раундов завышала результат втрое, причём и на нетронутых путях.
  Минимум из 25–40 раундов в том же процессе устойчив и совпадает с
  медианой на тихой машине. Ждать тишины бессмысленно — машина может
  быть занята десятки минут; вместо этого мерить минимумом и делать A/B
  двух сборок подряд в одних условиях (`git stash push lib/` → замер →
  `git stash pop`).
- **Отдельный сценарий гейта может уехать на 20–28 % от межджобового
  шума.** `brace.double.general` показал в CI ×0.78, а прямой A/B на
  dart2js — ×1.01. Прежде чем чинить «регрессию» из отчёта гейта,
  воспроизвести её локальным A/B.
- **Эталон гейта односторонний**: ускорение его не роняет, поэтому после
  намеренного изменения производительности он не «падает», а тихо
  устаревает. Перезаписывать с CI-железа (на ноутбуке те же отчёты
  разъезжаются до 16 %).
- **`sprintf` вариадичен.** `sprintf('%.0f', [2.5])` передаёт список как
  одно значение и падает; для списка — `vsprintf`.
- **Порядок ошибок в double-путях — контракт**: валидация precision в
  `dartSdk` идёт до проверки `isFinite`, чтобы плохая точность на `nan`
  всё равно бросала. При правках веток `write` не переставлять.
- **`CharSink` single-string инвариант**: `_single != null ⇒ _length == 0`.
  Любой новый метод записи обязан звать `_materialize()` первым или
  документировать, почему он без неё безопасен.
- **Приоритет встроенных типов над расширениями.** Formatter, принимающий
  всё, всё равно не вызывается для `String` или `int` — до него доходит
  только явное `{:name}`. Это регулярно ломает наивные пробы: чтобы
  дотянуться до расширения без спецификатора, нужен тип, которого движок
  не знает (`Object()`).
- **VM-only тесты**: `integer_format_test.dart`, `sprintf_integer_test.dart`,
  `template_ir_vm_test.dart` — литералы за 2^63 не компилируются dart2js.
- **Нет performance GREEN — нет коммита.** Правило проекта: изменение,
  заявленное как ускорение, коммитится только с замером; если замер не
  подтвердил — откатывать (так были отклонены мемоизация `_FormatSpec`,
  кэш `decimalPower`, `/packages/` в `.pubignore`).
