# format

[![CI](https://github.com/vi-k/format/actions/workflows/ci.yaml/badge.svg)](https://github.com/vi-k/format/actions/workflows/ci.yaml)

Перевод [README.md](README.md) на русский язык. В pub-архив не входит;
источник истины — английский оригинал, и якоря реестров расхождений
указывают на него.

`format` приносит в Dart мини-языки Python-подобных фигурных скобок и
printf, оставляя преобразование чисел по правилам Dart SDK поведением по
умолчанию. Поддерживаются позиционные и именованные значения, выравнивание
с учётом Unicode, числа с учётом локали и собственные форматтеры.

## Использование

```dart
import 'package:format/format.dart';

format('{} {}', 'hello', 'world');
format('{1} {0}', 'hello', 'world');
formatWith('{name}: {value}', named: {'name': 'answer', 'value': 42});
```

Публичный API форматирования состоит из:

```dart
format(String template, [Object? value1, ..., Object? value10]);
formatWith(
  String template, {
  List<Object?> positional = const [],
  Map<String, Object?> named = const {},
});
sprintf(String template, [Object? value1, ..., Object? value10]);
vsprintf(String template, List<Object?> values);
```

В шаблонах поддерживаются литеральные ширина и точность:

```dart
format('{:08d}', 42);       // 00000042
format('{:>10.2f}', 12.34); //      12.34
format('{:*^9s}', 'hello'); // **hello**
```

Удвоенные скобки дают литеральную скобку:

```dart
format('{{value}} = {0}', 42); // {value} = 42
```

То же удвоение работает и внутри спецификации, но там обе формы обязаны
балансироваться: `{{` требует последующего `}}`, потому что спецификацию
завершает первая же неэкранированная `}`. В обычном тексте они независимы,
поэтому одиночное `{{` там допустимо, а одиночная `{` — нет.

## Форматирование текста

Заполнитель, выравнивание и ширина применяются к тому, что получилось из
плейсхолдера, а точность обрезает текст, а не округляет его:

```dart
format('{:>8s}', 'hi');     //       hi
format('{:.3s}', 'abcdef'); // abc
```

Дополнение нулями — числовая опция, поэтому текстовая спецификация
отвергает её, а не дополняет молча нулями:

```dart
format('{:05s}', 'abc');  // бросает InvalidSpecifierException
```

Ширина и точность читаются как ASCII-цифры. Другие Unicode-цифры — ошибка
спецификации, но они остаются пригодны в индексе поля или ключе, где
называют аргумент, а не количество:

```dart
format('{:٥d}', 1);                        // бросает InvalidSpecifierException
formatWith('{٠}', positional: ['first']);  // first
```

## Символьные значения

Конверсия `c` превращает число в символ, который оно кодирует, — в обоих
мини-языках:

```dart
format('{:c}', 0x41);  // A
sprintf('%c', 0x41);   // A
```

Значение обязано быть скаляром Unicode. Одиночный суррогат или значение
выше `0x10FFFF` отвергается, а не даёт сломанную строку; дополнение нулями
и здесь остаётся числовой опцией:

```dart
format('{:c}', 0xD800);    // бросает UnsupportedFormatValueException
format('{:c}', 0x110000);  // бросает UnsupportedFormatValueException
format('{:05c}', 0x41);    // бросает InvalidSpecifierException
```

## Единицы измерения текста в Unicode

По умолчанию ширина и точность считают скалярные значения Unicode.
Настройте графемные кластеры, когда эмодзи и составные символы должны
считаться одним видимым символом каждый:

```dart
final graphemeFormat = Format(textUnit: TextUnit.graphemeClusters);

format('{:.3s}', '👩‍👩‍👧‍👦ab');              // 👩‍👩  — три скаляра
graphemeFormat.format('{:.3s}', '👩‍👩‍👧‍👦ab');  // 👩‍👩‍👧‍👦ab — три кластера
graphemeFormat.format('{:*<5s}', '👩‍👩‍👧‍👦');   // 👩‍👩‍👧‍👦****
```

Единица измерения решает и то, что считается одним символом-заполнителем,
поэтому многоскалярному заполнителю нужен графемный режим:

```dart
graphemeFormat.format('{:🇰🇿^13s}', 'Қазақстан');  // 🇰🇿🇰🇿Қазақстан🇰🇿🇰🇿
format('{:🇰🇿^13s}', 'Қазақстан');                // бросает InvalidSpecifierException
```

`TextUnitOperations` открывает то же измерение, которым пользуется движок, —
для кода, которому нужно раскладывать текст рядом с ним:

```dart
TextUnit.graphemeClusters.length('👩‍👩‍👧‍👦ab');  // 3
TextUnit.unicodeScalars.length('👩‍👩‍👧‍👦ab');    // 9
```

## Профили форматирования double

Десятичные конверсии `double` по умолчанию идут через Dart SDK. В
частности, `f`, `e` и `g` делегируют в `toStringAsFixed`,
`toStringAsExponential` и `toStringAsPrecision`, когда точность задана.
`g` без точности и пустые конверсии используют `toString()`:

```dart
format('{:.0f}', 2.5);          // 3
format('{:e}', 1.0);            // 1e+0
format('{:.3g}', 1.0);          // 1.00
format('{}', double.infinity);  // Infinity
```

Значит, действуют и ограничения точности Dart SDK: `f`, `e` и `%`
принимают от 0 до 20, а `g` и `n` — от 1 до 21. Как и `toStringAsFixed`,
`f` может перейти к экспоненциальной записи для величин от `10^21`.

Выбирайте `DoubleFormatMode.compatible`, когда нужны в точности
Python-овское форматирование фигурными скобками и округление и написание
как в printf C++:

```dart
final compatible = Format(
  doubleFormatMode: DoubleFormatMode.compatible,
);

compatible.format('{:.0f}', 2.5);          // 2
compatible.format('{:e}', 1.0);            // 1.000000e+00
compatible.format('{:.3g}', 1.0);          // 1
compatible.format('{}', double.infinity);  // inf
```

Сравнить оба профиля на текущей машине можно бенчмарком с цветным
ANSI-выводом:

```console
cd benchmark/suite
dart run bin/double_modes_benchmark.dart
```

Для конечных значений `double` в сценариях бенчмарка
`DoubleFormatMode.dartSdk` быстрее режима `compatible` либо укладывается в
принятый по умолчанию 5-процентный порог эквивалентности. Отчёт печатает и
отформатированные результаты, и медианные времена; этот вывод о
производительности не распространяется на `NaN` и `Infinity`. В VS Code
есть и конфигурация запуска **Benchmark: double modes**.

В режиме Dart SDK неконечные значения по умолчанию — `NaN` и `Infinity`.
Их короткое написание выбирается независимо; режим `compatible` всегда
использует короткое:

```dart
final shortSpecials = Format(
  doubleSpecialValueSpelling: DoubleSpecialValueSpelling.short,
);

shortSpecials.format('{}', double.nan);        // nan
shortSpecials.sprintf('%F', double.infinity);  // INF
```

## sprintf

`sprintf` принимает аргументы напрямую, `vsprintf` — списком:

```dart
sprintf('%s: %#08x', 'answer', 42);       // answer: 0x00002a
vsprintf('%*.*f', [8, 2, 1.5]);           //     1.50
```

Подмножество в стиле C поддерживает `%%`, `%c`, `%s`, знаковые и
беззнаковые целочисленные конверсии, а также десятичные и
шестнадцатеричные конверсии чисел с плавающей точкой. Ширина и точность
могут быть литералами или аргументами через `*`. Десятичные конверсии с
плавающей точкой используют выбранный профиль double: по умолчанию —
семантику Dart SDK, в режиме `compatible` — детерминированное
округление к ближайшему чётному и написание `inf`/`nan` в духе C++23. В
профиле по умолчанию `sprintf('%e', 12.5)` возвращает `1.25e+1`, а не
C-шное `1.250000e+01`: когда нужен в точности C-шный десятичный вывод,
выбирайте `DoubleFormatMode.compatible`. Отрицательные беззнаковые
значения отвергаются, а не заворачиваются по модулю.

Этот диалект для Dart намеренно опускает `%n`, `%p`, модификаторы длины
C, индексирование аргументов через `$` из POSIX и `%b`/`%B` из C++26.
Ширина и точность строк используют настроенный `TextUnit`; `%c` принимает
скаляр Unicode; `%s` зовёт `toString()` для нестроковых значений Dart; а
`int` и `BigInt` не усекаются до машинной ширины C. Настроенный
`NumberLocale`, в том числе присланный из `format_intl`, может
локализовать знаки, разделители и цифры за пределами нормативного профиля
совместимости `LC_ALL=C`.

## Числовые локали

Тип представления `n` и флаги группировки `,`/`_` читают `NumberLocale`.
По умолчанию это C-локаль: группирует запятой, отделяет дробную часть
точкой и оставляет `n` без группировки:

```dart
format('{:,.2f}', 1234567.5);  // 1,234,567.50
format('{:n}', 1234567);       // 1234567
```

Реализуйте `NumberLocale` для своей локали или возьмите необязательный
пакет [`format_intl`](https://pub.dev/packages/format_intl), который
приспосабливает данные локалей `intl`, не добавляя `intl` в зависимости
этого пакета:

```dart
import 'package:format_intl/format_intl.dart';

final kazakh = Format(numberLocale: IntlNumberLocale('kk_KZ'));
kazakh.format('{:.8n}', 123456.789);
```

В printf-диалекте нет `n`, поэтому локаль читает каждая числовая
конверсия: `%d` и `%x` берут её цифры и знаки, `%f` и `%e` — ещё и
разделители. Сам он не группирует никогда: шаблон, который о
разделителях не просил, их не получит.

Локаль может локализовать знаки, разделители и цифры сверх того, что
задаёт ядро C-локали; фикстуры совместимости пиннят только поведение
C-локали.

## Собственные форматтеры

Реализуйте `Formatter<T>` и передайте его в неизменяемый экземпляр
`Format`:

```dart
final class JsonFormatter extends Formatter<Map<String, Object?>> {
  @override
  String get specifier => 'json';

  @override
  bool canFormat(Object? value) => value is Map<String, Object?>;

  @override
  String format(Map<String, Object?> value, FormatOptions options) =>
      value.toString();
}

final jsonFormat = Format(formatters: [JsonFormatter()]);
jsonFormat.format('{:json}', <String, Object?>{'answer': 42});
```

Собственные спецификаторы обязаны соответствовать `[A-Za-z][A-Za-z0-9_]*`.
Встроенные имена зарезервированы. Для плейсхолдера без явного
спецификатора приоритет у встроенных типов, затем идёт единственный
подходящий собственный форматтер, затем `toString()`. Поэтому форматтер
никогда не спрашивают о значении, которое движок уже умеет отрисовать:
даже принимающий всё оставит `{}` на `String` или `int` встроенному пути,
и только явное `{:name}` доберётся до такого значения. Когда два
форматтера принимают одно и то же значение, а плейсхолдер не называет ни
одного, движок бросает `AmbiguousFormatterException`, а не выбирает сам.

Ширину, заполнитель и выравнивание движок применяет уже после того, как
собственный форматтер вернул результат, а `FormatOptions` отдаёт знак,
альтернативную форму, ноль, группировку, точность и необязательный
дополнительный шаблон. Этот шаблон — текст после второго `:`; форматтер
читает его из `FormatOptions.payload` и толкует как угодно:

```dart
jsonFormat.format('{:json:pretty}', <String, Object?>{'answer': 42});
// JsonFormatter.format получает options.payload == 'pretty'
```

Дополнительный шаблон живёт внутри спецификации, поэтому наследует правило
балансировки выше: скобки доходят до него удвоенными, а одиночную передать
нельзя вовсе.

```dart
jsonFormat.format('{:json:a{{b}}c}', <String, Object?>{'answer': 42});
// options.payload == 'a{b}c'
jsonFormat.format('{:json:a{{b}', <String, Object?>{'answer': 42});
// бросает InvalidFormatException — у {{ нет парного }}
```

### Доступ к атрибутам

Рефлексии в Dart нет, поэтому `{value.attribute}` разрешается только через
зарегистрированный `AttributeLookup`. Без него движок бросает
`FormatLookupException`:

```dart
final class PointLookup extends AttributeLookup<Point> {
  @override
  bool canLookup(Object? value) => value is Point;

  @override
  Object? lookup(Point value, String attribute) => switch (attribute) {
    'x' => value.x,
    _ => throw ArgumentError.value(attribute, 'attribute'),
  };
}

final pointFormat = Format(lookups: [PointLookup()]);
pointFormat.formatWith('{p.x}', named: {'p': const Point(7)});  // 7
```

Исключение — `Map`: `{value.name}` на карте — сокращение для строкового
ключа `'name'`, и разрешается оно раньше, чем спросят любой lookup,
поэтому lookup, принимающий карты, для карты не вызовется.

```dart
formatWith('{value.name}', named: {
  'value': {'name': 'Ada'},
});  // Ada
```

### Собственные представления

Реализуйте `Representation<T>`, чтобы дать типу собственную форму `!r` и
`!a`. Встроенные представления имеют приоритет так же, как встроенные
форматтеры, а `!a` экранирует не-ASCII символы в том, что вернуло
представление:

```dart
final class MoneyRepresentation extends Representation<Money> {
  @override
  bool canRepresent(Object? value) => value is Money;

  @override
  String represent(Money value) => '${value.cents}¢';
}

final moneyRepr = Format(representations: [MoneyRepresentation()]);
moneyRepr.format('{!r}', const Money(250));  // 250¢
moneyRepr.format('{!a}', const Money(250));  // 250\xa2
```

### Отказы внутри расширения

Всё, что бросает расширение, перехватывается и перебрасывается как
`FormatExtensionException`, который несёт исходные `error` и `stackTrace`
вместе с местом в шаблоне. Исключение из этого — `FormattingException`:
расширение, сообщающее об отказе на собственном языке движка, пропускается
без изменений.

Ошибки, которые Dart поднимает за расширение, заворачиваются так же.
`canFormat`, принявший значение неверного типа, даёт `TypeError`, когда
движок зовёт `format`, а расширение, форматирующее через повторный вызов
движка на том же значении, даёт `StackOverflowError` — оба приходят как
`FormatExtensionException`, а не убегают из движка в сыром виде.

## Числовая семантика JavaScript

dart2js представляет `int` и целочисленный `double` одним и тем же
JavaScript-овским `number`. Format канонически считает это неразличимое
значение целым: пустое, целочисленное, `!r` и контейнерное форматирование
пишут и `42`, и `42.0` как `42`. Явные спецификаторы с плавающей точкой —
`f`, `e`, `g`, `%` — по-прежнему выбирают форматирование с плавающей
точкой. На Dart VM `42` и `42.0` остаются различимыми, и пустое
форматирование даёт `42` и `42.0` соответственно. `BigInt` остаётся
отдельным видом значений на любой платформе.

## Представления

Конверсия `!r` даёт представление в терминах Dart, а `!a` вдобавок
экранирует не-ASCII символы. Обе реализованы этим пакетом, а не
делегированы значению: Dart-эквивалента протокола объектов Python, который
можно было бы позвать, не существует.

```dart
format('{0!r} {0!a}', 'строка');
// 'строка' '\u0441\u0442\u0440\u043e\u043a\u0430'
```

Значения пишутся своими Dart-токенами, а контейнер сохраняет порядок
обхода той коллекции, из которой пришёл, а не переупорядочивается:

```dart
format('{} {} {}', true, false, null);  // true false null
format('{!r}', {'b': 1, 'a': 2});       // {'b': 1, 'a': 2}
format('{!r}', {'b', 'a'});             // {'b', 'a'}
```

Вложенные значения `double` следуют выбранному профилю double и написанию
особых значений. Пустые `Map` и `Set` оба представляются как `{}`. Эта
неоднозначность намеренная: непустые значения остаются различимыми по
своему содержимому.

## Кэш шаблонов

Разобранные шаблоны кэшируются — именно это делает повторное
форматирование дешёвым: в собственном бенчмарке пакета первый вызов стоит
примерно вдвое-втрое дороже закэшированного, в зависимости от
мини-языка. Кэш ограничен, потому что шаблоны могут приходить из данных, а
неограниченный кэш был бы неограниченной утечкой.

```dart
templateCacheCapacity;        // 512 записей по умолчанию, на мини-язык
templateCacheCharacterLimit;  // 1 Ми символов по умолчанию, на мини-язык
templateCacheSize;            // сколько разобранных шаблонов лежит сейчас
templateCacheCharacters;      // сколько текста шаблонов они держат
clearTemplateCache();         // выбросить всё
```

Границ две, потому что число записей ничего не говорит об их размере.
Нагрузка из нескольких очень больших сгенерированных шаблонов остаётся
далеко внутри ёмкости, удерживая сотни мегабайт, — поэтому вторая граница
поставлена на текст шаблонов: вытесняет та, что сработала первой. Единица
измерения — символы, то, что видно снаружи; закэшированная запись держит в
памяти примерно в 5,5 раза больше, поскольку текст достижим из ключа, из
фрагментов, из литеральных узлов и из скомпилированных литералов. Значит,
по умолчанию выходит около 5,7 МиБ на мини-язык.

Шаблон длиннее всего бюджета форматируется, но не кэшируется никогда:
опустошать кэш ради одной записи, которая всё равно не поместится, значит
отнять у всех остальных шаблонов их разбор и не выиграть ничего.

Обе границы действуют в пределах изолята и общие для всех экземпляров
`Format` — разобранный шаблон не зависит от того, какой движок его
разобрал. Поднимайте ёмкость, когда рабочий набор больше значения по
умолчанию, а шаблоны повторяются; набор, который её перебирает по кругу,
удерживает примерно `capacity / size` себя, потому что полный кэш
вытесняет случайную запись, а не по порядку.

Ставьте любую из границ в ноль, когда шаблоны генерируются и никогда не
повторяются, — иначе кэширование будет платить только за вытеснение:

```dart
templateCacheCapacity = 0;  // выбрасывает закэшированное и ничего не держит
```

Понижение любой из границ выбрасывает записи сразу, а не при следующей
вставке.

`templateCacheSize` отличает «кэш мал для этой нагрузки» от «эта нагрузка
никогда не повторяет шаблон» — снаружи эти случаи выглядят одинаково.
Вместе с `templateCacheCharacters` он отличает и кэш, полный маленьких
шаблонов, от кэша, занятого горсткой больших: этим двум нужны
противоположные поправки. Чтобы увидеть, какую разницу кэш даёт на текущей

## Миграция на Format 3.0

Версия 2.0.0 на pub.dev не публиковалась, поэтому переход с
опубликованной 1.6.0 означает принятие изменений 2.0 и 3.0 разом; оба
набора описаны в CHANGELOG.

Версия 3.0 убирает `formatNamed` и трактует `List`, переданный в `format`,
как одно значение. Передавайте значения по отдельности или используйте
`formatWith` для позиционных и именованных коллекций:

```dart
format('{} {}', 'hello', 'world');
formatWith(
  '{name}: {value}',
  named: {'name': 'answer', 'value': 42},
);
```

Отказы форматирования пользуются типизированной иерархией
`FormattingException`. Собственные форматтеры, lookup'ы, представления,
локали и единицы измерения текста настраиваются построением экземпляра
`Format`, а не изменением глобальных реестров.

Версия 3.0 по умолчанию использует десятичное преобразование `double` из
Dart SDK. Приложениям, которые полагаются на округление, раскладку
экспоненты, точность за пределами Dart SDK или написание `inf`/`nan` в
духе Python и C++, следует строить `Format` с
`DoubleFormatMode.compatible`. Эта настройка одинаково действует на
форматирование фигурными скобками, `sprintf` и вложенные представления
`!r`/`!a`.
