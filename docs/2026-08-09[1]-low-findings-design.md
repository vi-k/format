# Дизайн: разбор секции Low проектного ревью

Статус: принят 2026-08-09, исполняется.

## Цель

Секция Low отчёта `docs/2026-08-05[5]-project-review.md` — единственная,
которая после закрытия Critical, High и почти всей Medium осталась
неразобранной целиком. В ней тридцать пунктов, L1–L30 (в шапке отчёта они
не пронумерованы итогом, поэтому «24» из прежних заметок — недосчёт).

Разобрана она считается тогда, когда **у каждого из тридцати пунктов в
отчёте стоит вердикт**. Вердикт — одна из трёх форм, ровно как это
делалось с пунктами Medium:

- `**Исправлено 2026-08-09:**` — что сделано и чем проверено; для
  пунктов о производительности с замером;
- `**Отклонено 2026-08-09:**` — почему правка не окупается или ломает
  то, что дороже; для перф-пунктов с замером, не подтвердившим выигрыш;
- `**Закрыто ранее:**` — когда и где пункт закрылся попутно другой
  работой, без отдельного захода.

Ни один пункт не остаётся без строки. Молчаливое вычёркивание запрещено:
через полгода «пункта нет в списке» и «пункт рассмотрели и отклонили»
неразличимы, а второе — знание.

## Принятые решения

Пять пунктов упирались не в код, а в выбор; выбор сделан до начала работы.

**L18 — правим код, а не документацию.** Целочисленные printf-конверсии
начинают читать локаль так же, как это уже делают вещественные. Это
меняет вывод на не-C-локалях, поэтому требует тестов и строки в
CHANGELOG; C-локаль и фикстуры совместимости не затрагиваются, потому
что в них знак и цифры совпадают с ASCII.

**L5 — фрагмент обрезаем с маркером.** Предел — 80 символов, считая
маркер: фрагмент длиннее обрезается до 79 символов плюс `…`. Короче
предела — не трогается вовсе, так что подавляющее большинство
диагностик остаётся дословным. Это изменение
наблюдаемого контракта диагностики: `fragment` перестаёт быть точной
вырезкой из шаблона. Отсюда две обязанности — строка в CHANGELOG и
сверка с parity-фаззером, который сравнивает `fragment` между IR и
legacy: обрезка должна применяться на обоих путях одинаково, иначе
фаззер найдёт расхождение, которого в поведении нет.

**L12 — убираем аллокации, арность оставляем.** `_collectOptionalValues`
переписывается так, чтобы строить один список известной длины: без
промежуточного литерала и без роста. Подпись и, следовательно, тип
tear-off не меняются, тест `test/api_test.dart` остаётся в силе. Число
десять остаётся сознательным разменом. Правка попадает под правило
RED/GREEN — вместе с L11.

**L27 — рабочая документация делится по времени жизни.** Живые
документы теряют дату и уезжают в `docs/`: `HANDOFF.md` → `docs/handoff.md`,
`TODO.md` → `docs/backlog.md`. Замороженные артефакты — дизайны, планы,
отчёты ревью — остаются датированными и плоскими, как сейчас. У каждого
замороженного документа появляется строка статуса сразу под заголовком
(`Статус: исполнен 2026-08-06` / `Статус: частично; открыто M5, M18–M20`),
чтобы «что открыто» читалось из шапок, а не только из handoff. В корне
остаются README, README.ru, CHANGELOG и LICENSE. Этот документ следует
новой конвенции сам.

Попутно, тем же заходом: два отчёта ревью от 2026-08-05 (`[4]` на 506
строк и `[5]` на 1324) с одинаковым заголовком развести по существу —
первый и второй проход; строку `Дата:` из тела убрать, дату несёт имя
файла.

Плашка «For agentic workers», написанная в части планов по-английски,
**остаётся как есть**. Проза самих планов тоже смешанная, и перевод
одной плашки языковой разнобой не снимает, а переписывать тела
замороженных документов — не та работа, ради которой затевался этот
пункт: цель была в том, чтобы стало видно, что живое и что открыто.

**L28 — C/C++ Runner убран целиком.** `.vscode/settings.json` состоял
из сорока ключей стороннего расширения, включая мёртвую на macOS ветку
MSVC и пустые `cStandard`/`cppStandard` — то есть даже C++23 в нём задан
не был. Файл удалён; из `launch.json` удалена конфигурация
«C/C++ Runner: Debug Session» с абсолютными путями и несуществующим
`tool/build/Debug/outDebug`, заодно убрана висячая запятая, из-за которой
файл не был строгим JSON. `/tool/build/` внесён в `.gitignore`.
Единственный C++ в проекте — `tool/generate_sprintf_fixtures.cpp`, и
собирается он мимо редактора: `tool/verify_generated_artifacts.dart`
компилирует его во временный каталог, и джоба `generated-artifacts`
гоняет именно этот путь.

## Порядок работы

Идём строго по номерам, L1 → L30, без приоритетов. Пункт, решение по
которому не очевидно из кода, выносится вопросом по ходу, а не
откладывается.

Мержим прямо в `main`, без PR. Коммит — на пункт или на связную группу
соседних пунктов; коммит не уходит, пока не зелены проверки из раздела
ниже. Одновременно с правкой кода в тот же коммит идёт вердикт в отчёте:
разъехаться они не должны.

Работа делится на пять естественных групп, внутри каждой — номерной
порядок:

1. диагностика парсера — L3, L4, L5, L6, L7;
2. мёртвый код и остатки L2;
3. аллокации горячего пути — L1, L11, L12, L13, L14, L15, L16;
4. тесты и воспроизводимость — L22, L23, L24;
5. инфраструктура и документация — L17, L19, L20, L21, L25–L30.

Группы — это порядок чтения, а не приоритет: пункт из пятой группы не
ждёт, пока закроется первая, если он идёт раньше по номеру.

## Проверки

Каждый коммит:

```sh
dart format . && dart analyze --fatal-infos lib test example tool
dart test
dart test -p node test/char_sink_test.dart test/template_ir_compile_test.dart \
  test/template_ir_diff_test.dart test/template_ir_fuzz_test.dart \
  test/js_number_dispatch_test.dart
```

Коммит, трогающий `benchmark/` или `tool/`, добавляет
`dart test benchmark/test tool/test`. Коммит, трогающий публичный API или
`.pubignore`, — `dart run tool/verify_package_archive.dart`.

Пункты L1 и L11–L16 заявлены как выигрыш по производительности и потому
попадают под правило проекта **нет GREEN — нет коммита**: A/B двух сборок
подряд в одних условиях (`git stash push lib/` → замер → `git stash pop`),
минимум из 25–40 раундов в одном процессе, а не медиана. Замер идёт в
вердикт. Если выигрыша нет — вердикт «Отклонено» с цифрой, а не
молчаливый откат: так уже закрывались мемоизация `_FormatSpec`, кэш
`decimalPower` и `/packages/` в `.pubignore`.

## Риски

**Мёртвый код L2 страхует оракул.** Часть недостижимых веток существует
потому, что legacy-путь — исполняемый оракул parity-фаззера, и ветка,
недостижимая на горячем пути, может быть достижима на нём. Каждая ветка
проверяется прогоном diff-тестов после удаления, а не рассуждением о
достижимости.

**L5 и L18 меняют наблюдаемое поведение.** Первый — контракт
диагностики, второй — вывод на не-C-локалях. Оба требуют строки в
CHANGELOG; оба должны быть применены одинаково на IR и на legacy, иначе
паритет сломается там, где поведение на самом деле не разошлось.

**L22 обещает больше, чем чинит.** Относительные пути в тестах
называются блокером прогона под node, но перенос этих файлов в node-набор
— отдельная работа со своими фикстурами; здесь чинится только
зависимость от рабочего каталога.

**Переезд handoff трогает ссылки.** На `HANDOFF.md` ссылаются шесть
документов в `docs/`, `test/template_ir_vm_test.dart` и `.pubignore`;
на `TODO.md` — `.pubignore` и сам handoff. Переименование без правки
ссылок оставит битые указатели, которые никто не проверяет.
