  расходились уже внутри `^0.20.2`.

  `UnsupportedConversionException` на SDK с 3.6.0 по 3.9.0. Причина — switch
  по `String?` с `case null`, который эти версии компилируют неверно. Разбор —
  в `docs/records/2026-08-18[1]-wasm-null-switch-and-sdk-floor-report.md`.

### Ночной гейт ничего не решает — вопрос владельцу

Ночные прогоны на `main` зелёные, но `performance-gate` в них только печатает
предупреждение «Not comparable with the recorded reference, so nothing is
decided» — так в каждом из 11 сверенных прогонов с 2026-08-17 по 2026-10-15.
Причины две: эталон записан на Dart 3.13.0, а stable в CI с 2026-08-29 не ниже
3.13.2 (на 2026-10-24 — 3.13.7), и `benchmark/gates.dart` сравнивает строку
версии целиком; кроме того, часть ночей попадает на CPU без эталона
(`AMD EPYC 9V74`, `Intel Xeon 6973P-C`). С каждым патчем stable эталон будет
устаревать заново.

Предложено 2026-10-15, ответа пока нет — решает владелец: переснять эталон
на нынешнем stable (до следующего патча), запинить Dart в job гейта на версию
эталона (гейт перестанет смотреть на новые SDK) или сравнивать версию Dart
до минора. Пункт про односторонний эталон в `docs/conventions.md` («устаревший
эталон безопасен, просто менее полезен») исходит из сравнимости и при этой
находке неточен. Разбор с выборкой прогонов —
в `docs/records/2026-10-15[1]-issue-8-dependabot-and-gate-report.md`.

Правки `lib/` после записи эталона пересъёмки сами по себе не требовали:
ускорение `c` под JavaScript одностороннее, типизированные предикаты матрицы
не касаются, страж null-конверсии идёт через сценарий `brace.conversion`
(`{!s:.2s}`) и замерен 2026-08-18: на VM неотличим (минимумы 184.9 против 184.3
нс, девять перемешанных прогонов на вариант), под dart2js быстрее исходной
формы (145.0 против 147.0 нс). `benchmark/scenarios.dart` после `9143e74`
не менялся, поэтому незнакомых id гейт не встретит.
