# Format 2.0 Implementation Plan

> **Состояние на 2026-08-16:** исполнен. 2.0.0 в pub не публиковалась, её
> изменения вошли в 3.0.0. Чекбоксы в теле не проставлялись — открытым пунктом
> их читать нельзя.
> **Что это:** исполнимый план реализации Format 2.0.
> **Связанные записи:** `2026-07-31[1]-format-2-design.md`.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Заменить старый `format` и экспериментальный `format2` единым быстрым движком с API `format`/`formatNamed` и публичным глобальным реестром пользовательских formatter.

**Architecture:** Встроенные specifier обрабатываются прямым dispatch в одном processor, а пользовательские formatter хранятся в приватном singleton с публичными статическими методами `Format.registerFormatter` и `Format.unregisterFormatter`. Processor разбирает шаблон, форматирует значение и централизованно применяет Unicode-aware width/fill/alignment.

**Tech Stack:** Dart 3.7.2+, `characters`, `intl`, `test`, `benchmark_harness`.

## Global Constraints

- Публичны только верхнеуровневые `format(String, List<Object?>)` и `formatNamed(String, Map<String, Object?>)`.
- `format2`, `format2m`, String extensions, positional `v2...v10` и `Map<Symbol, Object?>` удаляются.
- Width и precision задаются только десятичными литералами в шаблоне.
- Пользовательские specifier соответствуют `[A-Za-z][A-Za-z0-9_]*` и не могут переопределять встроенные имена.
- Реестр formatter глобален в пределах isolate; singleton не является публичным.
- Built-in automatic matching имеет приоритет; несколько custom matches дают `AmbiguousFormatterException`; отсутствие match использует `toString()`.
- Ядро применяет width, fill и align после formatter.
- Изменения выполняются через red-green-refactor; каждый production change предваряется падающим тестом.
- Существующие незакоммиченные изменения пользователя сохраняются и не включаются в тематические коммиты без необходимости.

- [ ] **Step 3: Реализовать минимальные публичные types**

`FormatOptions` должен иметь точную immutable сигнатуру:

```dart
final class FormatOptions {
  final String? sign;
  final bool alternate;
  final bool zero;
  final String? grouping;
  final int? precision;
  final String? template;

  const FormatOptions({
    this.sign,
    this.alternate = false,
    this.zero = false,
    this.grouping,
    this.precision,
    this.template,
  });

```

`Formatter<T>` должен предоставлять только согласованный extension contract:

```dart
abstract base class Formatter<T> {
  const Formatter();

  String get specifier;
  bool canFormat(Object? value);
  String format(T value, FormatOptions options);
}
```

Чтобы промежуточный commit оставался компилируемым, существующий внутренний
`Formatter` переименовать в `BuiltInFormatter`, обновить его subclasses и тип
`_formatters` в `lib/src/format.dart`. `BuiltInFormatter` не экспортировать из
`lib/format.dart`; новый generic `Formatter<T>` экспортировать через `show`.

Создать `FormattingException implements Exception` и классы
`InvalidFormatException`, `InvalidSpecifierException`,
`FormatterAlreadyRegisteredException`, `BuiltInSpecifierException`,
`AmbiguousFormatterException`, `UnsupportedFormatValueException` со
следующими структурированными полями:

```dart
sealed class FormattingException implements Exception {
  final String message;
  const FormattingException(this.message);
}

final class InvalidFormatException extends FormattingException {
  final String fragment;
  final String reason;
}

final class InvalidSpecifierException extends FormattingException {
  final String specifier;
}

final class FormatterAlreadyRegisteredException extends FormattingException {
  final String specifier;
}

final class BuiltInSpecifierException extends FormattingException {
  final String specifier;
}

final class AmbiguousFormatterException extends FormattingException {
  final Object? value;
  final List<String> specifiers;
}

final class UnsupportedFormatValueException extends FormattingException {
  final String specifier;
  final Object? value;
}
```

У каждого subclass должен быть const constructor, инициализирующий поля и
понятный `message` базового класса.

```dart
final class CustomValue {}

final class JsonFormatter extends Formatter<Map<String, Object?>> {
  @override
  String get specifier => 'json';

  @override
  bool canFormat(Object? value) => value is Map<String, Object?>;

  @override
  String format(Map<String, Object?> value, FormatOptions options) =>
      value.toString();
}

final class IntAliasFormatter extends Formatter<int> {
  @override
  final String specifier;

  IntAliasFormatter(this.specifier);

  @override
  bool canFormat(Object? value) => value is int;

  @override
  String format(int value, FormatOptions options) => value.toString();
}

final class MatchingFormatter extends Formatter<CustomValue> {
  @override
  final String specifier;

  MatchingFormatter(this.specifier);

  @override
  bool canFormat(Object? value) => value is CustomValue;

  @override
  String format(CustomValue value, FormatOptions options) => specifier;
}

setUp(() => Format.unregisterFormatter('json'));
tearDown(() => Format.unregisterFormatter('json'));

test('registers and removes a custom formatter', () {
  Format.registerFormatter(JsonFormatter());
  expect(Format.unregisterFormatter('json'), isTrue);
  expect(Format.unregisterFormatter('json'), isFalse);
});

test('duplicate registration has a dedicated exception', () {
  Format.registerFormatter(JsonFormatter());
  expect(
    () => Format.registerFormatter(JsonFormatter()),
    throwsA(isA<FormatterAlreadyRegisteredException>()),
  );
});

test('built-in specifiers cannot be changed', () {
  expect(
    () => Format.registerFormatter(IntAliasFormatter('d')),
    throwsA(isA<BuiltInSpecifierException>()),
  );
  expect(
    () => Format.unregisterFormatter('d'),
    throwsA(isA<BuiltInSpecifierException>()),
  );
});
```
