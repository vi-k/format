## Цель

Убрать парсинг шаблона из горячего пути повторяющихся вызовов
`format()`/`sprintf()`: кэшировать AST по строке шаблона и лениво
мемоизировать разобранный `_FormatSpec` статических спецификаций в
узле. Ожидаемый эффект: у горячих шаблонов остаётся только само
форматирование (ориентир: `{:10d}` ~0.36 → ~0.10–0.15 мкс).

## Решения пользователя

- Политика ёмкости: cap + полная очистка при переполнении (как кэш
  `re` в Python). Ёмкость 512, зашита константой.
- Публичного API нет: кэш — прозрачная внутренняя деталь. Тестовые
  ручки — приватные debug-seam'ы по прецеденту проекта.
- Бенчмарк: существующая матрица становится hot-замером; добавляется
  cold-секция с уникальными шаблонами на каждую итерацию.
- Quick-режиму бенчмарка разрешено до 1 минуты (прежний потолок 45 с
  снят).

## Ключевые факты (проверены в сессии)

- AST обоих парсеров зависит только от строки шаблона: сканирование
  идёт по code units, `TextUnit` влияет лишь на парсинг строк
  спецификаций. Кэш можно ключевать одной строкой шаблона и разделять
  между экземплярами `Format`.
- `TextUnit` имеет ровно два значения → мемоизация `_FormatSpec` в
  узле — два слота.
- Изоляты Dart не разделяют изменяемую память: статический кэш
  per-isolate, блокировки не нужны.
- Жадный парсинг спецификаций менял бы порядок ошибок (спецификация
  валидировалась бы до резолва аргументов) — поэтому мемоизация
  строго ленивая, при первом успешном парсинге на прежнем месте
  потока.

## Архитектура

### Кэш AST

Новый part-файл `lib/src/template_cache.dart`:

```dart
const _templateCacheCapacity = 512;
final _braceTemplateCache = <String, _BraceTemplate>{};
final _printfTemplateCache = <String, _PrintfTemplate>{};
```

Обёртки над `_parseBraceTemplate`/`_parsePrintfTemplate` (вызовы в
`_BraceProcessor.format` и `_PrintfProcessor.format` переключаются на
них):

- hit → вернуть готовый AST (чистый lookup, без учёта порядка);
- miss → `if (cache.length >= _templateCacheCapacity) cache.clear();`
  затем парсинг и запись.

Кэшируются только успешные парсинги. Синтаксически неверный шаблон
кидает исключение на каждом вызове — негативного кэша нет, поведение
не меняется.

### Мемоизация спецификаций

`_FieldNode` получает два изменяемых слота:

```dart
_FormatSpec? _scalarSpec;
_FormatSpec? _graphemeSpec;
```

`_BraceProcessor._formatField` для статической спецификации (пустой
список узлов или один `_LiteralNode`) читает слот своего
`engine.textUnit`; при промахе парсит через `parseFormatSpec` в том же
месте потока, что и сейчас, и сохраняет результат. Динамические
спецификации (вложенные поля) продолжают собираться и парситься на
каждый вызов.

`formatValue` в `value_formatter.dart` разделяется:

- `formatValue(value, String specification, engine, context)` —
  прежняя сигнатура, тонкая обёртка: parse + delegate;
- `formatParsedValue(value, _FormatSpec spec, engine, context)` —
  вся существующая логика.

Ошибка парсинга спецификации не мемоизируется и воспроизводится на
каждом вызове, с тем же контекстом, что и сейчас.

### Согласованность

- Кэш общий для всех экземпляров `Format` (AST не зависит от
  `textUnit`, locale, doubleFormatMode); слоты мемоизации корректны,
  т.к. парсинг спецификации детерминирован по (строка, textUnit).
- Immutability-контракт AST сохраняется: под asserts списки
  оборачиваются `List.unmodifiable` (существующий `_sealedInDebug`);
  мемо-слоты — единственная изменяемая часть узла, записываются
  идемпотентно.

## Бенчмарк

- Существующие 26 сценариев — hot-замер (шаблон постоянен, кэш
  работает). Ожидаемое заметное ускорение колонок format 3.0
  относительно baseline (у sprintf 7.0 и format 2.0 кэша нет).
- Новая cold-секция после матрицы: только два раннера format 3.0
  (brace и printf), шаблон уникален на каждую итерацию
  (`'v$i={:10d}'` / `'v$i=%10d'`, значение 12345). Замер через
  существующий `MyBenchmarkBase` (счётчик в `run()`); OK-проверка не
  выполняется (вывод меняется), печатается только время. Уникальные
  шаблоны заодно постоянно прогоняют путь переполнения и полной
  очистки кэша.
- Полный quick-прогон обязан укладываться в 60 секунд; текущие
  константы quick 45/165 мс не меняются, если лимит соблюдается.

## Тесты (TDD)

Debug-seam'ы (не экспортируются из `format.dart`):

```dart
int debugBraceTemplateCacheSize();
int debugPrintfTemplateCacheSize();
void debugClearTemplateCaches();
```

Тесты (`test/template_cache_test.dart`):

- повторный вызов возвращает `identical` AST (оба синтаксиса);
- 513-й уникальный шаблон схлопывает кэш до одной записи;
- невалидная спецификация кидает одинаковое исключение на первом и
  повторном вызове (AST уже в кэше);
- результаты форматирования идентичны на первом и повторном вызове,
  включая Unicode-fill (`{:é^10s}`) на обоих `TextUnit` и
  динамическую спецификацию (`{:{}d}`);
- один и тот же шаблон через два экземпляра `Format` с разными
  `TextUnit` даёт корректные результаты каждому (мемо-слоты
  независимы).

Timing-ассертов в unit-тестах нет. Performance RED/GREEN — 
диагностическим скриптом и сравнительным бенчмарком.

## Вне охвата

- Публичный API управления кэшем.
- Компиляция шаблонов в IR.
- Кэширование `_ResolvedPrintfConversion` (динамические `*`-опции).
- Негативный кэш ошибок парсинга.

## Проверка результата

- `dart test` в корне и `example/` — зелёные; Node-прогон
  brace/printf-тестов — зелёный.
- `dart analyze` — без новых замечаний.
- Диагностика: горячие `{:10d}`/`{:s}` кратно быстрее; cold-цифры
  сопоставимы с сегодняшними до-кэшевыми.
- Полный quick-бенчмарк ≤ 60 с, единственный ERROR — намеренный
  sprintf 7.0 на минимальном int.
