# Executive summary

Это зрелый, тщательно спроектированный пакет с редкой для соло-проекта инженерной культурой:
двухпутевая архитектура (быстрый IR + легаси-эталон) с дифференциальными тестами и фаззером,
sealed-иерархия ошибок с полным контекстом, побитово-точная реализация double-форматирования
(`Binary64`), образцово вендоренные бенчмарк-baseline'ы и честная методология замеров.
Все 470 тестов зелёные, паритет IR↔legacy на 30 000 случайных кейсов — без единого расхождения.

Главные риски — не в ядре, а по краям:

1. **Единственный подтверждённый функциональный баг Python-паритета**: zero-padding в сочетании
   с группировкой у целых систематически «перелетает» заданную ширину (H1) — все 422 расхождения
   фаззинга против CPython принадлежат этому классу.
2. **Тихая порча вывода на вебе**: `{:d}`/`%d` на dart2js для |v| ≥ 2⁵³ печатает неточные цифры,
   а от 10²¹ — экспоненциальную запись вплоть до мусорной группировки `1e,+21` (H2).
3. **Диагностика обесценена**: ни одно исключение иерархии не переопределяет `toString()` —
   в логах будет `Instance of 'InvalidSpecifierException'` (H3).
4. **Гигиена публикации и воспроизводимости**: внутренний 62-КБ HANDOFF.md уезжает в pub-архив (H4),
   CI отсутствует полностью при node-зависимом тестовом контуре (H5), в git закоммичен
   5,7 МБ бинарник (M1).

Общий уровень качества кода и тестов — высокий; список исправлений компактен, и почти всё
чинится точечно (самый крупный фикс — H1 — использует уже существующий в кодовой базе механизм).

# Project overview

**Назначение**: форматирование строк в Dart двумя мини-языками — Python-стиль
`format('{:>10.2f}', x)` (позиционные/именованные поля, lookup-цепочки `a.b[c]`, конверсии
`!s/!r/!a`, вложенные спецификации `{:{}.{}f}`) и C-стиль `sprintf('%*.*f', ...)`.
Два профиля double: `dartSdk` (дефолт, делегирование `toStringAsFixed/AsExponential/AsPrecision`)
и `compatible` (побитово-точный Python/C++-паритет). Опциональный подпакет `format_intl`
подключает CLDR-локали через `intl`, не добавляя `intl` в зависимости ядра.

**Архитектура** (`lib/src/` — одна библиотека `engine.dart` из 22 `part`-файлов):

- Вход: `format`/`formatWith`/`sprintf`/`vsprintf` (`api.dart`, `format.dart`) — тонкие обёртки,
  создающие процессор на вызов; `Format` — иммутабельная конфигурация (форматтеры, локаль,
  TextUnit, double-профили).
- Парсинг: `brace_parser.dart`/`printf_parser.dart` → AST; глобальный по-изолятный кэш шаблонов
  на 512 записей (`template_cache.dart`).
- Исполнение: `template_ir.dart` компилирует AST в IR-программу (лениво, с мемоизацией по
  `TextUnit`): «горячие» опы (литералы, строки, int, double со статическими спецификациями)
  пишут напрямую в `CharSink` (Uint16-буфер); всё сложное (группировка, `n`, локали, конверсии,
  lookup, динамические спецификации) уходит в `_BraceFallbackOp`/`_PrintfFallbackOp` — легаси-путь
  (`field_resolver.dart` → `format_spec.dart` → `value_formatter.dart` → `number_format.dart`).
- Легаси-путь целиком сохранён как эталон и доступен через debug-швы для дифференциальных тестов.
- Настройки движка читаются в момент записи, а не компиляции — поэтому один кэш корректно
  обслуживает все экземпляры `Format`.
- `binary64.dart` — ручная разборка битов double (BigInt-significand, round-half-even) для
  compatible-профиля; `python_identifier.dart` — сгенерированные из CPython таблицы идентификаторов.

Вокруг ядра: бенчмарк-инфраструктура с JSON-гейтами (`benchmark/`, вендоренные замороженные
baseline'ы format2 и sprintf7), визуальная ANSI-матрица (`example/`), фикстуры совместимости,
сгенерированные реальными CPython 3.14 и C++23/libc (`test/fixtures/`, `tool/`).

# Critical and high-severity findings

Critical-находок нет.

## H1. Zero-padding + группировка у целых расходится с Python (переполнение ширины)

- **Severity**: High. **Уверенность**: high (подтверждено лично: Dart против CPython 3.14.6).
- **Файлы**: `lib/src/number_format.dart:59-76` и `89-96` (вызовы `applyNumericWidth` из
  `formatBraceInteger` без `fitRegroupedZeroPadding: true`); сам механизм — `number_format.dart:150-168`.
- **Проблема**: float-путь подбирает число нулей бинарным поиском так, чтобы итог с сепараторами
  дал минимальную длину ≥ width (семантика CPython). Целочисленный путь (включая локальный `n`)
  считает padding до группировки и после вставки сепараторов систематически перелетает ширину.
- **Сценарий**: любой шаблон `0`-заполнения с `,`/`_`/локальной группировкой у `d/b/o/x/X/n`.
  Проверено: `{:010,d}` 1234 → `000,001,234` (11 зн.), Python — `00,001,234` (10);
  `{:015,d}` 123456 → `00,000,000,123,456` (18), Python — `000,000,123,456` (15);
  `{:06,d}` −5 → `-00,005`, Python — `-0,005`; аналогично `{:#014_x}`, `{:016_b}`, локальный `{:015n}`.
  Фаззинг 7 999 кейсов: все 422 расхождения — этот класс; double-кейсы чисты.
- **Последствия**: нарушение заявленного Python-паритета и самой семантики width; ломает
  выравнивание таблиц/колонок. В `python_format.json` таких шаблонов нет, в реестре дивергенций
  не задокументировано — т.е. это именно пропуск, а не осознанное решение. Единственный
  закреплённый тест `{:08,d}` (test/integer_format_test.dart:148) случайно совпадает с Python.
- **Исправление**: передать `fitRegroupedZeroPadding: true` в оба вызова `applyNumericWidth`
  из `formatBraceInteger` — существующий механизм даёт ровно питоновские ответы. Горячие IR-опы
  не задеты (группированные целые и так в fallback). Добавить кейсы в фикстуры.

## H2. Web (dart2js): `{:d}`/`%d` печатает экспоненциальную запись и неточные цифры

- **Severity**: High (web-only). **Уверенность**: high (подтверждено лично: dart2js -O2 + Node).
- **Файлы**: `lib/src/number_format.dart:105-109` (`_formatIntMagnitude` → `value.toString()`);
  `lib/src/template_ir.dart:77-84, 171-190, 1053-1064` (web-ветки с комментарием
  «value.toString() prints exactly» — утверждение неверно).
- **Проблема**: на dart2js `int.toString()` — это JS `String(n)`: для |v| ≥ 10²¹ даёт
  экспоненциальную форму, а в диапазоне (2⁵³, 10²¹) — shortest-roundtrip вместо точных цифр.
- **Сценарий**: проверено: `format('{:d}', 1e21)` → `1e+21`; `{:,d}` → **`1e,+21`** (группировка
  применяется к мусору); `{:d}` 2⁶⁰ → `1152921504606847000` при точном значении `…846976`;
  при этом `{:x}` того же значения точен (`1000000000000000`), и `{!r}` точен (идёт через
  `BigInt.from`) — три представления одного значения взаимно противоречивы.
- **Последствия**: тихая порча вывода на вебе; существующие `js_number_dispatch_test.dart` и
  запись `dart-js-integral-number-canonicalization` в дивергенциях покрывают слияние int/double,
  но не это.
- **Исправление**: в web-ветке `_exceedsWebSafeInt` формировать цифры через
  `BigInt.from(value).toString()`/`toRadixString(radix)` (как уже делает representation-путь);
  либо явно задокументировать и отклонять ≥ 10²¹.

## H3. Иерархия исключений не переопределяет `toString()`

- **Severity**: High (по влиянию на эксплуатацию). **Уверенность**: high (подтверждено лично).
- **Файл**: `lib/src/errors.dart:19-118` (все 10 классов).
- **Проблема**: наследуется `Object.toString()`. Тщательно собираемый контекст (message, reason,
  fragment, offset, template, argumentIndex) невидим в момент, когда он нужнее всего.
- **Сценарий**: любое непойманное исключение форматирования в логах/crash-репортах приложения.
  Проверено: `sprintf('%999999999d', 5)` → `Instance of 'InvalidSpecifierException'`.
- **Последствия**: обесценена главная сильная сторона иерархии ошибок; отладка по логам невозможна
  без воспроизведения.
- **Исправление**: базовый `toString()` в `FormattingException`: message + payload подкласса
  (reason/key/value…) + fragment/offset/срез шаблона. Осторожно с полем `value`, чей собственный
  `toString()` может бросать (см. M3).

## H4. Внутренний HANDOFF.md публикуется на pub.dev

- **Severity**: High (для публикации). **Уверенность**: high (подтверждено `dart pub publish --dry-run`).
- **Файл**: `HANDOFF.md` (62 КБ) — присутствует в дереве dry-run; `.pubignore` его не исключает.
- **Проблема/последствия**: внутренний сессионный документ с личными путями
  (`/Users/user/development/my/format`), rtk-командами, состоянием веток и loadavg машины уедет
  каждому пользователю пакета.
- **Исправление**: строка `/HANDOFF.md` в `.pubignore` (или перенос в уже исключённый `docs/`).

## H5. CI отсутствует полностью — при node-зависимом тестовом контуре

- **Severity**: High (системный риск процесса). **Уверенность**: high.
- **Факты**: `.github/` и любые CI-конфиги отсутствуют. При этом корневой `dart test` сам
  компилирует dart2js- и AOT-артефакты и требует `node` в PATH
  (`test/benchmark_scenarios_test.dart:392-486`), а канонический node-прогон (53 теста) и
  JS-ветки существуют только как ручные команды в HANDOFF.
- **Сценарий**: контрибьютор без node получает красный `dart test` без объяснений; регрессия
  на чужом окружении не будет замечена до релиза; вся дисциплина «нет GREEN — нет коммита»
  держится на одной машине.
- **Последствия**: невоспроизводимость заявленных гарантий; связано с M6 (JS-ветки тестов мертвы).
- **Исправление**: минимальный GitHub Actions: `dart analyze`, format-check, `dart test` (VM),
  `dart test -p node <4 файла>`, матрица по SDK; тяжёлые compile-тесты — отдельным job'ом
  и/или за тегом `@Tags(['toolchain'])`.

# Medium and low-severity findings

## Medium

**M1. Закоммиченный бинарник `example/bin/benchmark.exe` (5,7 МБ)** — крупнейший blob истории
(добавлен в `96fcd3d`); каждый клон тянет его вечно, артефакт молча устаревает. Из pub-архива
исключён, из git — нет. Исправление: удалить из индекса, добавить в `.gitignore`.
Уверенность: high.

**M2. В brace-пути нет предохранителя на ширину — асимметрия собственной политики безопасности**
(`lib/src/format_spec.dart:90-92, 378-393`; `lib/src/template_ir.dart:615-722`; контраст:
`printf_processor.dart:7` и `number_format.dart:633-638` — лимит 100 000 для printf-опций и
precision). Проверено лично: `sprintf('%100001d', 1)` — типизированный отказ, но
`format('{:100001d}', 1)` → строка 100 001 зн., `format('{:{}d}', 1, 5000000)` → 5 МБ строка.
`{:2000000000}` — попытка гигантской аллокации → нетипизированный `OutOfMemoryError`; в серверном
сценарии с чужой шириной — DoS. Python ведёт себя так же, но пакет сам ввёл более строгий контракт
в printf. Исправление: применить общий лимит к width в `parseFormatSpec` и к динамическим
спецификациям. Уверенность: high.

**M3. printf `%s` глотает причину упавшего `toString()`** (`printf_formatter.dart:53-59`,
`template_ir.dart:938-947` против brace-аналога `value_formatter.dart:160-173`): исходная ошибка
и stack trace теряются (`catch (_)` → `UnsupportedConversionException`), тогда как brace-путь
оборачивает в `FormatExtensionException` с сохранением причины. Вдобавок исключение хранит сам
`value`, чей `toString()` бросает — печать `e.value` падает повторно. Исправление: единообразно
использовать `FormatExtensionException`/добавить `error`/`stackTrace`. Уверенность: high.

**M4. Дефолтный `sprintf` не C-совместим для `%e`/`%g`, и это не задокументировано в реестре
дивергенций** (`dart_double_format.dart:17-60`; фикстуры гоняются только в compatible —
`sprintf_compatibility_test.dart:11-13`, а дефолт — `dartSdk`). Проверено: `%e` 12.5 → `1.25e+1`
(C: `1.250000e+01`); `%.30f` → отказ (C поддерживает). README упоминает профили, но
`sprintf_divergences.json` — канонический список отступлений — записи не содержит. Исправление:
запись в реестр + явный пример в README. Уверенность: high.

**M5. JS-перф-гейт мёртв: жёсткий пин Node v24.8.0** (`benchmark/gates.dart:246-249`), локально
уже v26.5.0 — гейтуемый js-отчёт создать невозможно, валидация отвергает его до сравнения чисел.

**M6. JS-ветки тестов не исполняются ни в одном задокументированном прогоне**

**L1. Юникод-цифры Python принимаются в именах/индексах полей, но не в width/precision**
(`format_spec.dart:363-366` — только ASCII; contrast `python_identifier.dart`). Проверено:
Python принимает `'{:٥d}'`, Dart — отказ, при том что `'{٥}'` работает. Задокументировать
или использовать `pythonDecimalDigitValue` в общем парсере. Уверенность: high.

**L2. Недокументированные дивергенции `{:c}`** (`value_formatter.dart:303-338`): суррогаты и
zero-fill Python допускает, Dart типизированно отвергает — решение разумно, но в реестре
дивергенций записей нет. Уверенность: high.

**L3. `%a` для subnormal: spelling отличается от платформенного libc и не задокументирован**
(`printf_formatter.dart:266-306`): `0x0.0000000000001p-1022` против `0x1p-1074` (то же значение,
допустимо по C23); `%.0a` при фиксированной экспоненте −1022 округляет subnormal в `0x0p-1022`.
Из 738 libc-кейсов все 9 расхождений — этот класс (причём в одном кейсе Dart округляет
правильнее Apple libc). Задокументировать в реестре. Уверенность: high (факты).

**L4. Локализация `%a` смешивает системы цифр; асимметричный регистр экспоненты**
(`printf_formatter.dart:308-339`, `number_format.dart:563-570`): ar_EG `%.2a` → `0x١٫٩ap؜-٤`
(арабские цифры + латинская hex-буква в одном ряду); CLDR-символ `E` не приводится к нижнему
регистру для `e`-запросов (`uk %e` → `1,234568Е+04`). Уверенность: high (факты), medium (намерение).

**L5. Целочисленные конверсии sprintf не локализуются вовсе** (`printf_formatter.dart:86-164`):
в арабской локали минус у double — `−`, у int — ASCII `-`; README обещает «may localize signs,
separators, and digits». Либо локализовать, либо уточнить README. Уверенность: high (факт).

**L6. Платформенно-зависимый тип ошибки при переполнении литеральной ширины printf**
(`printf_parser.dart:113-127`): на VM `int.tryParse('999…')` → null → `InvalidFormatException`
на парсинге; на dart2js tryParse вернёт округлённое число и ошибка возникнет позже другим типом.
Защита от OOM сохраняется в обоих случаях. Сравнивать с лимитом прямо в `_parseOption`.
Уверенность: medium (web-ветка не исполнялась).

**L7. Мёртвый код**: `value_formatter.dart:61-64` — обе ветки условия бросают идентичное
исключение (хелперы `:195-220` — мёртвый груз); недостижимые ветки в printf-конвейере
(`template_ir.dart:1492-1496`, `826-829`; `printf_formatter.dart:39-43`; защитные `StateError`
в `printf_parser.dart:150`, `printf_formatter.dart:217, 317` — доказуемо недостижимы).
Уверенность: high.

**L8. Дублирование (риск дрейфа)**: `_staticSpecificationText` (`brace_processor.dart:106-111`) —
копия `_staticBraceSpecification` (`template_ir.dart:544-549`); `Format._reservedFormatterNames`
(`format.dart:7-23`) дублирует `_builtInTypes` (`format_spec.dart:165-181`) — те же 15 элементов,
две точки правки; в `_classifyPrintfConversion` (`template_ir.dart:1339-1461`) блок разрешения
static width/precision скопирован трижды. Уверенность: high.

**L9. Политика кэша шаблонов: полный сброс вместо LRU + неограниченный размер записи**
(`template_cache.dart:3-24`): 513-й уникальный шаблон сбрасывает весь прогретый кэш (проверено);
ротация >512 шаблонов — перманентный reparse; одноразовый гигантский шаблон удерживается до
сброса. LinkedHashMap-вытеснение старейшей записи — та же O(1). Потокобезопасность не проблема:
кэш по-изолятный. Уверенность: high.

**L10. Тест кэша привязан к литералу 512 и односторонний** (`template_cache_test.dart:26-33`):
константа продублирована, переполнение printf-кэша не проверено. Уверенность: high.

**L11. Репозиторий не проходит `dart format` текущего SDK — 19 файлов из 104** (lib/ чист;
тесты, example, format_intl, вендоренные baseline'ы). pana на pub.dev проверяет форматирование
файлов архива — возможна потеря баллов. Нормализовать отдельным коммитом или исключить каталоги
из архива. Уверенность: high (факт), medium (эффект на скор).

**L12. Скачок версии 1.6.0 → 3.0.0 с никогда не публиковавшейся 2.0.0**: пользователю 1.6.0
нужны оба раздела миграции (2.0 и 3.0), README покрывает только 3.0. Одной фразой отметить в
CHANGELOG/README. Уверенность: high.

**L13. Недокументированные отклонения от Python в brace-пути**: `'{-1}'`/`'{ }'` (у Python —
валидные ключи), bool с числовой шириной (`'{:10}'` для True), кавычки в item-ключах — решения
разумны и дают лучшие ошибки, но раздела «отклонения от Python» в README нет. Уверенность: high.

**L14. Лишние аргументы sprintf молча игнорируются** (`vsprintf('%d', [1, 2, 3])` → `1`):
соответствует C, но для «строгого диалекта» (отвергающего даже `%+u`) непроверенный хвост —
самая частая реальная ошибка вызова; не упомянуто в документации. Уверенность: high.

**L15. Гигиена репозитория**: `example2/` — однофайловый дебаг-таргет launch.json рядом с
полноценным `example/`; `.vscode/` с абсолютными путями `/Users/user/...`; корневой
`pubspec.lock` закоммичен (для библиотеки не рекомендуется; в example — корректно исключён);
пустой нетрекаемый `lib/src/utils/`; разнобой `lints` (^4 в корне, ^5 в example, доступна 6.x);
BOM в `LICENSE`; `example/CHANGELOG.md` — заглушка; захардкоженная метка SDK `3.12.2` в
`benchmark_scenarios_test.dart:401`. Уверенность: high.

**L16. Мелочи API**: `AmbiguousFormatterException.specifiers` (`errors.dart:104`) — при выбросе
из `field_resolver.dart:86-92` содержит `runtimeType.toString()` лукапов, а не спецификаторы —
имя вводит в заблуждение. Уверенность: high.

**L17. format_intl: тонкое покрытие** — 4 локали; нет локали с выключенной группировкой и
негативных кейсов `localizeDigits`; ожидания вида `'1 234'` зависят от CLDR-данных
`intl ^0.20.2` без пина — minor-обновление intl даст ложное падение. Уверенность: medium.

# Architecture review

**Сильные стороны.**

- **Двухпутевая архитектура с контрактом паритета** — главное инженерное решение проекта:
  быстрый IR-путь и полный легаси-путь, эквивалентность которых непрерывно доказывается
  дифференциальными тестами и фаззером (сравниваются не только результаты, но и типы исключений
  со всеми полями контекста). Это позволяет агрессивно оптимизировать, не рискуя семантикой:
  30 000 случайных кейсов этого ревью не нашли ни одного расхождения.
- Иммутабельный `Format` + чтение настроек в момент записи (а не компиляции) делают глобальный
  кэш шаблонов корректным для любого числа конфигураций; партиционирование мемоизации по
  `TextUnit` последовательно.
- Разделение ответственности между парсером/классификатором/исполнителем чистое; «всё сложное —
  в fallback» — честная стратегия, исключающая полурабочие горячие пути.
- Публичная поверхность (`lib/format.dart`) аккуратна: наружу не торчит ничего лишнего;
  debug-швы существуют только в `package:format/src/engine.dart` и прокомментированы.
- Минимальные зависимости: единственная runtime-зависимость `characters` обоснована;
  `format_intl` вынесен в отдельный workspace-пакет, чтобы не тянуть `intl` в ядро — образцовое
  управление зависимостями.

**Слабые места и спорные решения.**

- **Одна библиотека из 22 `part`-файлов**: весь движок в общей области видимости — любой
  приватный символ доступен из любого файла, границы модулей внутри `lib/src/` не принуждаются
  компилятором. Для данного размера (6 700 строк) терпимо, но это осознанный размен
  инкапсуляции на удобство швов; рост кода будет его усугублять.
- **Стоимость контракта паритета**: IR-опы — «транслитерации» легаси-функций
  (`_BraceDoubleOp.write` ↔ `formatBraceDouble` и т.д.); каждая правка семантики требует
  зеркальной правки в двух местах. Риск купирован тестами, но это постоянный налог на
  сопровождение (см. также L8 — местами дублирование уже неосознанное).
- Асимметрия политики безопасности (M2): printf и precision защищены лимитом, brace-width — нет.
- Политика кэша «полный сброс» (L9) — простейшая из возможных; для библиотечного кода, который
  не контролирует нагрузку, LRU был бы уместнее при той же сложности.
- H2 показывает границу подхода «транслитерация + комментарий»: web-ветка была обоснована
  комментарием («toString() prints exactly»), который оказался фактически неверным, а
  непокрытая тестами платформа не смогла это поймать — аргумент в пользу M6/H5.

# Testing review

**Покрыто отлично**: brace/printf-парсеры (включая негативные грамматики, UTF-16-смещения,
переполнения опций), целочисленный путь (minInt во всех основаниях, BigInt, группировки),
compatible-double (ties-to-even, субнормали, precision 1000, ~310-значные развороты maxFinite),
текст/Unicode (astral fills, суррогаты, оба TextUnit), конверсии `!s/!r/!a` (рекурсивные
контейнеры), реестр форматтеров (ambiguity, defensive copy), ошибки как контракт
(offset/fragment/specifier проверяются почти в каждом негативном тесте), IR-паритет
(дифф-матрицы + фаззер 1600 кейсов с гейтами от вырождения корпуса), кэш. Гигиена образцовая:
0 skip, 0 закомментированных тестов, изоляция состояния дисциплинированная. Счётчики HANDOFF
(396/14/53) подтверждены прогонами.

**Критические непроверяемые риски (в порядке приоритета)**:

1. **JS-платформа** (M6): ветки `isJavaScript` мертвы во всех задокументированных прогонах —
   и именно там жил H2. Самый высокоприоритетный новый тест — `-p node` для
   `js_number_dispatch_test` + web-кейсы `{:d}` за 2⁵³ и 10²¹.
2. **Исполняемость реестра дивергенций** (M7): 10 python-записей и 7 из 13 sprintf-записей —
   декларации без исполнения; протухание незаметно.
3. **Фаззер не генерирует**: именованные/вложенные поля, lookup-цепочки, `!r/!s/!a`,
   конверсии `o/b/X/c/%/a`, Unicode-значения, несколько плейсхолдеров, кастомные форматтеры —
   резолвер полей в IR-пути держится только на ручных дифф-кейсах.
4. **Реентерабельность**: вызов `format()` изнутри кастомного `Formatter` при глобальном кэше,
   попадающий на ветку полного сброса (`template_cache.dart:11-13`), не проверен ничем.
5. **Переполнение printf-кэша и format_intl-локаль без группировки** — существующие ветки
   без единого теста.

Фикстуры: процесс генерации серьёзный (пины CPython 3.14 / компилятора, `LC_ALL=C`, метаданные
в JSON, платформозависимые выходы через `allowed`-множества, верификатор для второй платформы),
но пошаговая инструкция регенерации разбросана по design-doc'ам и нигде не собрана.

# Performance and reliability

- Производительность — центральная дисциплина проекта: перф-гейты
  (`benchmark/gates.dart:8-12`) с анти-флаки-дизайном (провал только при воспроизведении в двух
  независимых прогонах, медианы ≥7 interleaved-раундов, provenance с ревизией и рантаймом),
  контрольная группа шума из замороженных baseline'ов и честно сформулированный порог
  обнаружения (~9%) в HANDOFF. Абсолютные числа замеров в рамках ревью не перепроверялись
  (методология воспроизводима и самодокументирована).
- **Мёртвый JS-гейт** (M5) — единственная сломанная часть этой инфраструктуры.
- Надёжность: нетипизированный `OutOfMemoryError` через brace-width (M2) — единственный
  найденный класс входов, роняющий процесс. Фаззинг 30 000 кейсов не дал ни одного
  нетипизированного исключения на прочих траекториях.
- Конкурентность: race conditions отсутствуют по построению — глобальное мутабельное состояние
  (кэши, мемоизация в AST) по-изолятное, внутри изолята исполнение синхронное; async-кода в
  пакете нет. Изолятная безопасность подтверждена аналитически (модель памяти Dart), эмпирически
  с изолятами не проверялась.
- Управление ресурсами: аллокации ограничены временем вызова; единственный долгоживущий ресурс —
  кэш шаблонов с неограниченным размером записи и обвальным сбросом (L9): деградация
  предсказуемая (reparse), не утечка.
- Масштабирование: ротация >512 шаблонов (типовой антипаттерн — интерполяция данных в шаблон)
  переводит кэш в режим постоянных промахов — стоит задокументировать или перейти на LRU.

# Maintainability

- Читаемость высокая; выдающаяся культура комментариев: каждый шов, каждое решение о паритете
  и каждая мемоизация объяснены на месте (комментарии-эссе в `engine.dart`, `template_ir.dart`).
- Технический долг локализован и невелик: мёртвые ветки (L7), дубли (L8), мёртвый конфиг
  анализатора (M10), две копии Format 2 (M11), гигиена (L15). Крупных структурных проблем нет.
- Главный постоянный налог — зеркальность IR ↔ legacy (см. Architecture review).
- Документация процесса (HANDOFF, design-doc'и в `docs/superpowers/`) необычно полная, но
  HANDOFF уже разошёлся с реальностью в git-разделе (M9) — цена ручного ведения.
- Отсутствие dartdoc на публичном API (M12) — заметный пробел для библиотеки, претендующей
  на pub.dev.

# Positive findings

Решения, которые стоит сохранить:

1. **Parity-харнес** (`test/parity_harness.dart:147-165`): сравнение runtimeType, типизированного
   payload и всех шести полей контекста ошибки; switch по sealed-иерархии без default — новый
   подкласс ошибки ломает компиляцию харнеса, а не выпадает из сравнения.
2. **`Binary64`** — точная десятичная математика double прошла все проверки ревью: субнормали,
   min-normal, maxFinite (~310 цифр посимвольно с CPython), `-0.0`, banker's rounding на BigInt,
   корректный exact-tie-детектор fast-path.
3. **Фаззер с гейтами от вырождения корпуса** (distinct/rendered floors) и «matched»-генератором —
   защита от тихой деградации фаззинга в сплошные ошибки.
4. **Вендоринг baseline'ов**: пины коммитов, verbatim-лицензии BSD-2-Clause, README с политикой
   «benchmark-only», изоляционный тест (`benchmark_isolation_test.dart`), гарантирующий, что
   baseline'ы не протекают в публичный API.
5. **Фикстуры совместимости, сгенерированные реальными инструментами** (CPython 3.14, C++23/libc)
   с типизированной кодировкой значений (bigint, `-0`, nan) и валидируемыми загрузчиками.
6. **Web-семантика int/double** (`_isWebInt`, `_exceedsWebSafeInt`, «отрицательное пространство»
   против переполнения minInt) — продуманная, задокументированная в README канонизация.
7. Защита от инъекции: динамические спецификации `{0:{1}}` не перепарсиваются как шаблон —
   `{`/`}` из аргументов не интерпретируются.
8. Иммутабельность `Format`, defensive copies, валидация конфигурации с типизированными ошибками.
9. Минимальность зависимостей и workspace-разделение `format`/`format_intl`.
10. Методология замеров с контрольной группой шума и явным порогом обнаружения — интеллектуальная
    честность, редкая в перф-документации.
