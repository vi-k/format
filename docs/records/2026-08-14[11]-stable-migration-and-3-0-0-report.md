## SDK переведён с 3.12.2 на stable (пин 2026-08-12; миграция 2026-08-14)

**Итог 2026-08-14.** Внешний отказ `package:test` перестал воспроизводиться,
а внутренняя миграция выполнена одним изменением. `benchmark/wasm_host.mjs` и
host из `benchmark/suite/tool/run.dart` теперь вызывают `compile(bytes)`,
`compiled.instantiate({})` и `instance.invokeMain(...)`; primary-запись
матрицы и четыре самостоятельных CI jobs следуют за `stable`, минимальный
Dart 3.7.2 сохранён отдельно. Форматтер 3.13 принят. Ниже остаётся история
причины временного пина.

Stable ушёл с 3.12.2 на 3.13.0 **между двумя прогонами CI** — предыдущий
в 06:43 зелёный, следующий в 08:13 красный, и правка тут ни при чём.
Вскрылось три разных вещи, и только одна из них решает.

- Форматтер 3.13 иначе сворачивает длинные `test('...', () { ... })` —
  расходится один файл, `benchmark_scenarios_test.dart`. Мелочь.
- Анализатор 3.13 видит `prefer_if_elements_to_conditional_expressions`
  там, где 3.12.2 молчал: пять мест в `benchmark_gates_test.dart`, все
  вида `for (...) cond ? a : b` в литерале списка. **Исправлено** — новая
  форма принимается обоими SDK, так что это годится и после открепления.
- **Исторически решающее: в 3.13 сменился API загрузчика dart2wasm.** `instantiate`
  больше не экспорт рядом с `compile`, а метод у того, что `compile`
  вернул. Бутстрап, который генерирует `package:test`, зовёт старый, и
  первый `dart test -c dart2wasm` **не грузился вовсе, на каждом файле**.
  Позднее тот же `package:test` 1.31.2 на окончательном Dart 3.13.0 прошёл;
  этот внешний симптом больше не блокирует миграцию.

Решение владельца тогда: **CI был припинен к `3.12.2`** вместо `stable`,
потому что терять wasm-прогон нельзя — это единственное место, где всё дерево
тестов встречается с настоящими 64-битными целыми на веб-подобной цели, и
именно он поймал `--9223372036854775808`.

**Внешняя предпосылка и внутренняя миграция выполнены.** Репозиторий
формат-чист под Dart 3.13.0; `.git/hooks/pre-commit` по-прежнему сверяет формат
тем `dart`, который найдёт в `PATH`, поэтому локальный commit запускается с
stable первым в `PATH` либо после явной проверки тем же executable.

## Что сделано 2026-08-14 (M1 второго ревью)

**M1 закрыт целиком.** Уже исправленный корневой индекс не менялся. Числовой
item-key теперь сканируется прямо в исходном шаблоне, не создаёт подстроку и
удерживает только ограниченный значащий хвост. Для width/precision выбран
гибрид: спецификации длиной до 256 сохраняют прежний быстрый общий парсер, а
длинные читает `_FormatSpecCursor` с lookahead не более двух единиц. Полностью
потоковый вариант был отклонён из-за регрессии холодного разбора; две
оставшиеся реализации грамматики сверяет `debugFormatSpecParsersAgree` на
матрице обоих `TextUnit` и на границе 256/257.

Peak-RSS свежего VM-процесса на пяти миллионах цифр: width нули
28 475 392 → 0 Б, width девятки 68 009 984 → 0 Б, item-key нули
114 212 864 → 0 Б, item-key девятки 114 262 016 → 0 Б. Предел двух
регрессионных тестов — 20 МиБ; возврат прежней материализации их ломает.

Performance GREEN, кэш отключён. VM, минимум 30 раундов по 200 000:
grouping 317,88 → 319,33 нс (+0,46 %), precision 386,98 → 385,99,
Unicode fill 609,52 → 614,01 (+0,74 %), item-key 548,38 → 472,54.
dart2js `-O4 --no-minify`, минимум 25 раундов по 2 млн: 333,5 → 332,0;
586,5 → 572,0; 498,5 → 498,0; 575,0 → 554,0 нс соответственно.

Полный список проверок выполнен на Dart 3.12.2: format/analyze; VM 604;
node 421 + 4 пропуска; dart2wasm 403 + 1 пропуск; вспомогательные тесты 45;
`format_intl` 7; самостоятельный pub-архив с 604 тестами; генераторы;
покрытие 95,98 % при поле 94 %; benchmark suite 15 тестов и полные quick-
матрицы VM, JS и Wasm. После обновления локального stable до 3.13.0
дополнительный полный dart2wasm-прогон дал 403 + 1 на прежнем `package:test`:
внешний блок пина снят. Внутренние wasm-host'ы и форматтер остаются отдельной
атомарной миграцией; авторитетный полный прогон M1 выполнен на CI-пине 3.12.2.

## Что сделано 2026-08-14 (миграция внутренних инструментов на stable)

Два независимых красных сторожа воспроизвели несовместимость старого loader
API на Dart 3.13.0. Тест committed host'а падал с `TypeError: instantiate is
not a function`; wasm-прогон `list_snapshot` в benchmark suite — с отсутствием
named export `instantiate` у свежего `benchmark.mjs`. После прямого перехода
на объектный API оба сторожа зелёные. Compile-тесты JS и Wasm больше не
подделывают provenance литералом 3.12.2, а берут первый токен
`Platform.version`.

В `.github/workflows/ci.yaml` сохранён отдельный floor 3.7.2, primary-строка и
jobs `generated-artifacts`, `coverage`, `benchmark-suite`, `performance-gate`
переведены на `stable`. Форматтер Dart 3.13.0 изменил только ожидаемый
`benchmark/test/benchmark_scenarios_test.dart`.

Полный список из `## Как проверить всё` выполнен на Dart 3.13.0: format и
analyze чисты; VM 604; Node 421 + 4 пропуска; dart2wasm 403 + 1 пропуск;
вспомогательные тесты 45; `format_intl` 7; самостоятельный pub-архив с 604
тестами; генераторы; покрытие 95,98 % (3131/3262) при поле 94 %; benchmark
suite 15. Quick-матрицы завершились за VM 63,2 с, JS 72,9 с и Wasm 62,8 с.

Миграционный коммит
`9143e7407e162a1fdc6b11d57515143390a04c53` опубликован напрямую в `main`;
[push-CI 31804804963](https://github.com/vi-k/format/actions/runs/31804804963)
зелёный во всех пяти обязательных jobs. Следующий
[performance-run 31805224647](https://github.com/vi-k/format/actions/runs/31805224647)
также зелёный. Его восемь runtime reports имеют тот же source revision,
CPU `AMD EPYC 7763 64-Core Processor`, Dart 3.13.0, а JS/Wasm — Node.js
v24.8.0. Старый gate ожидаемо был несопоставим с эталоном Dart 3.12.2;
перезаписанный `benchmark/results/gate-baseline.json` оценивает те же отчёты
как `comparable` и содержит ровно восемь runtime/dialect-наборов.

## Что сделано 2026-08-14 (`c` под JavaScript)

Профиль локализовал лишнюю стоимость в общем `_unicodeScalar`: успешный
обычный `int` превращался в `BigInt`, а затем сравнивался с `BigInt`-границами
при каждой подстановке. Brace и printf теперь проверяют `int` прямыми
сравнениями, а настоящий `BigInt` сохраняет отдельный точный и
short-circuit-путь. Публичные тесты закрепляют обе стороны границ `0xd800`,
`0xdfff`, `0x10ffff` и оба исходных типа на VM, dart2js и dart2wasm.

Локальный одно-сценарный A/B выполнен на `arm64`, Dart 3.13.0 stable,
Node.js v26.5.0, dart2js `-O4 --no-minify`: 5 прогревов, 30 измеренных
раундов по миллиону операций, решает минимум. Во всех процессах checksum
`65000000`.

| сценарий | три before, нс | три after, нс | лучший before → after |
|---|---:|---:|---:|
| Format 3 `{:c}`, `int` | 134, 133, 135 | 57, 57, 56 | 133 → 56 (−57,9 %) |
| Format 3 `%c`, `int` | 112, 111, 108 | 29, 29, 29 | 108 → 29 (−73,1 %) |

Format 1.6 `{:c}` занял 143–144 нс против 56–57 нс Format 3. Контроль
настоящего `BigInt` не показал воспроизводимого замедления: brace-пары
116 → 120 и 117 → 117 нс, printf-пары 121 → 122 и 123 → 122 нс. Первый
вариант с заранее построенными тремя границами был отклонён именно потому,
что такой контроль поймал устойчивую регрессию. Итоговый performance-вердикт
GREEN; матрица gate не менялась, эталон переснимать не требуется.

Полный обязательный список проверок выполнен на итоговой реализации: format и
analyze чистые; VM — 607 тестов, dart2js — 424 + 4 пропущено, dart2wasm —
406 + 1 пропущен; auxiliary — 45, `format_intl` — 7, benchmark suite — 15.
Опубликованный архив самостоятелен и проходит свои 607 тестов, сгенерированные
артефакты совпадают, покрытие — 95,99 % (3134/3265 строк) при полу 94 %.
Quick-матрицы VM, JS и Wasm завершились за 61,8, 69,0 и 64,7 с. В строке `c`
JS-матрицы Format 3 дал 0,077 мкс для `{:c}` и 0,061 мкс для `%c` против
0,151 мкс Format 1.6; VM — 0,078/0,045 против 0,949 мкс, Wasm — 0,060/0,036
против 0,656 мкс.

## Что сделано 2026-08-14 (типизированные предикаты расширений)

`Formatter<T>.canFormat`, `AttributeLookup<T>.canLookup` и
`Representation<T>.canRepresent` теперь получают `T` и по умолчанию
возвращают `true`. Первичную проверку `value is T` выполняют приватные методы
базовых классов, где реальный generic-параметр ещё не стёрт до `dynamic`;
движок обращается к ним через три внутренних helper из `extensions.dart`.
Helper не попали в поддерживаемый публичный facade благодаря существующим
спискам `show`.

Несовпадение runtime type стало штатным «не подходит» и не вызывает
пользовательский код. Дополнительный typed-предикат по-прежнему может
отвергнуть подмножество своего `T`, а брошенная им ошибка сохраняет прежние
`FormatExtensionException`, исходный stack trace и контекст. Отдельные тесты
закрепляют default, subset, wrong-type guard, `Object?`, nullable `T`,
неоднозначность и оборачивание ошибок для всех трёх extension point.

Обычные реализации и примеры больше не повторяют `value is T`; содержательные
предикаты принимают свой настоящий тип. README объясняют обе ступени выбора,
а `CHANGELOG.md` содержит миграцию. Это ломающее изменение относительно
опубликованного 2026-08-14 `3.0.0`, но `pubspec.yaml` намеренно остаётся на
`3.0.0`: выбор версии и публикация вынесены за пределы задачи.

Дизайн:
`docs/records/2026-08-14[7]-typed-extension-predicates-design.md`; исполнимый
план: `docs/records/2026-08-14[8]-typed-extension-predicates-plan.md`.

Полный обязательный предкоммитный список GREEN: format — 116 файлов, 0
изменений; analyze чистый; VM — 616 тестов, dart2js — 433 + 4 пропущено,
dart2wasm — 415 + 1 пропущен; auxiliary — 45, `format_intl` — 7, benchmark
suite — 15. Pub-архив самостоятелен и проходит свои 616 тестов, генераторы
совпадают, покрытие — 96,00 % (3146/3277 строк) при полу 94 %. Quick-матрицы
VM, JS и Wasm завершились за 62,9, 68,1 и 63,1 с. Изменение не заявлено как
ускорение, матрица и эталон performance gate не менялись.

## Что сделано 2026-08-14 (дизайн единого справочника форматов)

Второй пункт `docs/backlog.md` взят в разбор: «полное описание форматов»
уточнено как полный справочник обеих мини-грамматик — `{...}` и `sprintf`,
включая grammar, flags/options, width, precision, grouping, type matrices,
пределы и классы ошибок. Исполненный первый пункт про typed-предикаты удалён
из живого backlog по прямому указанию владельца.

Владелец выбрал вариант с отдельным типизированным const contract-каталогом,
из которого генерируются отмеченные секции `README.md` и `README.ru.md`, а
параметризованные тесты выполняют те же строки через публичный API. Парсеры не
переводятся на общий data-driven runtime: полноту их конечных множеств
подтверждают непубличные debug-seams, остальную семантику — conformance-cases.
Generated-artifacts verifier должен проверять README без записи в checkout.

Согласованный дизайн записан в
`docs/records/2026-08-14[9]-format-reference-source-design.md`. Он прошёл
проверку placeholders, внутренней согласованности, scope и названных классов
ошибок и одобрен владельцем. Implementation plan записан в
`docs/records/2026-08-15[1]-format-reference-source-plan.md`: четыре
инкремента — catalog/validator, generator/README, conformance/parser seams и
общий generated-artifacts gate. Владелец выбрал вариант 1 — исполнение через
`superpowers:subagent-driven-development`. Код реализации ещё не начинался,
ни один implementer не запускался.

Планирование выявило границу pub-архива: `tool/` исключён, но корневые тесты
внутри архива запускаются. Поэтому каталог генерирует также
`test/support/format_reference_cases.dart`; корневой conformance-тест читает
эту неизменяемую проекцию, а единственным редактируемым источником остаётся
`tool/src/format_reference_contract.dart`. В plan перечислены exact grammar,
option/type matrices, limits, error classes, локализации, calls и outcomes;
self-review закрыл coverage, placeholder scan и согласованность имён/типов.

Полный предкоммитный прогон для design-коммита GREEN: `dart format .` — 116
файлов, 0 изменений; analyzer чистый; основные тесты — VM 616, dart2js 433
плюс 4 skip, dart2wasm 415 плюс 1 skip; auxiliary — 45, `format_intl` — 7,
benchmark suite — 15; независимая проверка архива — 616; generated artifacts
совпадают; покрытие — 96,00% (3146/3277); quick-матрицы VM/JS/Wasm —
63,7/68,1/64,8 секунды. Коммит документационный, performance A/B и эталон
гейта не требовались.
