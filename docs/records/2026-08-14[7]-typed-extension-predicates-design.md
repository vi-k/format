# Типизированные предикаты расширений

> **Состояние на 2026-08-16:** исполнен 2026-08-14.
> **Что это:** дизайн типизированных предикатов расширений — изменение,
> сделавшее версию 4.0.0 мажорной.
> **Связанные записи:** `2026-08-14[8]-typed-extension-predicates-plan.md`,
> `2026-08-15[4]-format-reference-and-4-0-0-report.md`.

## Контекст

Три публичные точки расширения устроены одинаково:

- `Formatter<T>` принимает `Object?` в `canFormat`, а затем `T` в `format`;
- `AttributeLookup<T>` принимает `Object?` в `canLookup`, а затем `T` в
  `lookup`;
- `Representation<T>` принимает `Object?` в `canRepresent`, а затем `T` в
  `represent`.

Из-за этого обычная реализация повторяет проверку, уже выраженную параметром
типа класса:

```dart
bool canFormat(Object? value) => value is Money;
```

Связь между ответом предиката и типом следующего вызова существует только в
документации. Ошибочный `true` пропускает значение дальше и превращается в
`TypeError` при вызове второго метода.

Эти точки расширения впервые опубликованы в `format 3.0.0` 2026-08-14; в
предыдущей опубликованной версии 1.6.0 их не было. Поэтому принято исправить
контракт сразу и чисто, без постоянного переходного API. Уже опубликованный
3.0.0 не меняется; номер и публикация следующего релиза не входят в эту
работу.

## Решение

Предикаты получают `T` и принимают всякое значение этого типа по умолчанию:

```dart
abstract base class Formatter<T> {
  const Formatter();

  bool canFormat(T value) => true;

  String format(T value, FormatOptions options);
}

abstract base class AttributeLookup<T> {
  const AttributeLookup();

  bool canLookup(T value) => true;

  Object? lookup(T value, String attribute);
}

abstract base class Representation<T> {
  const Representation();

  bool canRepresent(T value) => true;

  String represent(T value);
}
```

Обычное расширение больше не реализует `can*`: параметр `T` и есть его
полный фильтр. Переопределение остаётся для более узкого условия внутри типа:

```dart
final class MoneyFormatter extends Formatter<Money> {
  @override
  String get specifier => 'money';

  @override
  bool canFormat(Money value) => value.currency == 'KZT';

  @override
  String format(Money value, FormatOptions options) => value.toString();
}
```

Это намеренное изменение публичной сигнатуры. Переходный метод с другим
именем и мост через `Object?` не добавляются: они сохранили бы навсегда два
способа выразить один вопрос ради API, существовавшего меньше дня.

## Диспетчеризация

Перед пользовательским предикатом движок проверяет значение против реального
параметра типа экземпляра:

```dart
bool _accepts(Object? value) => value is T && canFormat(value);
```

Такая проверка живёт в каждом из трёх базовых классов, где `T` не потерян за
типом реестра `Formatter<dynamic>` или его аналогом. Движок обращается к ней
через три внутренние функции из `extensions.dart`. Фасады `format.dart` и
`engine.dart` уже экспортируют этот файл через списки `show`, поэтому функции
не входят в поддерживаемый публичный API.

Поток вызова одинаков для всех точек расширения:

1. Встроенный путь сохраняет нынешний приоритет и при возможности обрабатывает
   значение сам.
2. Внутренний guard проверяет `value is T`.
3. При несовпадении типа расширение не подходит, пользовательский код не
   вызывается.
4. При совпадении вызывается `can*(T value)`; `false` означает более узкий
   отказ расширения.
5. При `true` второй метод получает то же значение как `T` без нового
   пользовательского приведения.

`T == Object?` по-прежнему принимает в том числе `null`, `T == dynamic`
принимает любое значение, nullable-параметр сохраняет свою обычную семантику.
Особая числовая модель dart2js не получает нового правила: `value is T`
следует тем же платформенным правилам Dart, что и прежняя написанная
пользователем проверка.

## Ошибки и неизменные контракты

Несовпадение типа — штатный ответ «не подходит», а не ошибка расширения. Для
явно названного форматтера оно по-прежнему приводит к
`UnsupportedFormatValueException`; при автоматическом выборе поиск идёт
дальше или заканчивается прежним fallback. Lookup и representation сохраняют
свои нынешние типы итогового отказа.

Guard не исполняет пользовательский код и не требует оборачивания. Исключение
из `can*` после успешного guard по-прежнему проходит через существующий
`try`/`catch`: `FormattingException` перекидывается без обёртки, остальные
ошибки становятся `FormatExtensionException` с исходным stack trace и
контекстом шаблона.

Не меняются:

- приоритет встроенных типов, `Map`-lookup и встроенных representation;
- обнаружение двух подходящих расширений;
- порядок обхода реестров;
- правила ширины, локали, Unicode и форматирования результата;
- `specifier`, `FormatOptions` и конструктор `Format`.

## Документация и миграция

Dartdoc трёх классов объясняет две ступени: тип проверяет движок, `can*`
нужен только для дополнительного условия и по умолчанию возвращает `true`.
Примеры в `README.md` и `README.ru.md` удаляют повторяющиеся `value is T`.
Рядом добавляется короткий пример более узкого typed-предиката, чтобы его
назначение не потерялось вместе с boilerplate.

`CHANGELOG.md` называет изменение публичного контракта и показывает миграцию:
обычный `can*` удалить, дополнительное условие переписать с `Object?` на `T`.
Версию пакета эта работа не выбирает и публикацию не выполняет.

После реализации исполненный пункт вычёркивается из `docs/backlog.md`, а
`docs/handoff.md` синхронизируется с новым состоянием.

## Проверка

Тесты сначала должны краснеть на нынешнем API, затем закрепить для каждого из
трёх extension point:

- конкретный класс без `can*` компилируется и принимает свой `T`;
- значение другого типа отсекается до пользовательского кода;
- typed-предикат может отвергнуть часть значений своего `T`;
- два принятых расширения по-прежнему дают неоднозначность;
- исключение из typed-предиката сохраняет прежнюю оболочку и stack trace;
- `Object?` и nullable-параметры не теряют допустимый `null` там, где
  встроенный приоритет разрешает дойти до расширения.

README проверяются существующим тестом якорей и примеров. Итог проходит весь
список из `docs/handoff.md` на VM, dart2js и dart2wasm, включая архив,
генераторы, покрытие и benchmark suite. Изменение не заявляется ускорением,
поэтому отдельный performance-вердикт для коммита не требуется.
