## Что сделано 2026-08-15 (справочник форматов, Task 1)

стабильном порядке: проверяет обязательные переводы, уникальность semantic ids,
token'ов и case ids, ссылки на существующие случаи, направление evidence и
обязательные положительные/отрицательные границы.

Работа велась по TDD. Targeted RED —
`dart test tool/test/format_reference_contract_test.dart` — ожидаемо не
скомпилировался из-за отсутствующих model/catalog/validator. После реализации
тот же targeted-прогон зелёный: 3 теста из 3. Узкий analyzer
`dart analyze --fatal-infos tool/src tool/test/format_reference_contract_test.dart`
чистый.

Первый review-раунд расширил модель без prose-обхода:
`TypeContract.excludedOptionTokens` типизированно вычитает отдельные token из
разрешённой type-опции. Пустой brace-тип больше не объявляет payload;
нечисловые `s`, `c` и custom исключают sign-aware `=`, а `b`, `o`, `x`/`X` —
десятичную запятую grouping. Validator отвергает неизвестную type-опцию,
неизвестный token и повтор token в таком исключении. Targeted TDD после
добавления только поля дал четыре ожидаемых поведенческих отказа; окончательный
прогон — 7 тестов из 7, узкий analyzer чистый.

## Что сделано 2026-08-15 (справочник форматов, Task 2)

Создан детерминированный генератор справочника. Чистый renderer строит из
каталога одинаково упорядоченные английскую и русскую Markdown-проекции:
грамматики brace и printf, таблицы опций и флагов, обе type/conversion matrix,
пределы и публичные классы ошибок. Строки матриц показывают точные токены
опций по типу: `TypeContract.excludedOptionTokens` вычитает `=` у `s`, `c` и
собственного форматтера и `,` у недесятичных brace-целых, поэтому README не
обещает синтаксис, который парсер отвергает. Типизированные
`optionAppliesTo`/`tokenAppliesTo` уточняют зависимость от категории значения:
пустой presentation не обещает nameless-опции custom values, `n` ограничивает
`z` и precision значениями `double`, а `f/e/g/%` учитывают promotion целых в
floating formatter.

`tool/generate_format_reference.dart` поддерживает только `--write` и
`--check`. До первой записи он валидирует каталог, обе marker-пары,
semantic-порядок локализаций и все ссылки на заголовки полного README;
check-режим возвращает весь список устаревших путей и не пишет. Генерируемый
`test/support/format_reference_cases.dart` хранит 153 вызова и ожидаемых
исхода, inventory brace-типов и точную printf flag matrix, не импортируя
исключённый из pub-архива `tool/`.

Обе прежние ручные таблицы типов удалены. Их место занял generated-блок, а
ручные разделы с примерами сохранены и ссылаются обратно на соответствующие
матрицы. Минимальная правка каталога закрыла пропущенную ссылку Unicode:
printf-строка ведёт на `#unicode-text-units` /
`#единицы-измерения-текста-в-unicode`; brace-строка по-прежнему ведёт на
раздел форматирования текста.

Работа велась по TDD. Первый RED не компилировался из-за отсутствующих
renderer/generator import и функций. Финальный targeted GREEN — 23 теста

## Что сделано 2026-08-15 (публикация 4.0.0)

`format 4.0.0` и `format_intl 1.0.1` опубликованы из коммита `8bbddb8`.
Проверено по публичному API pub.dev; аннотированный тег `v4.0.0` запушен,
его peeled SHA на удалённом — тот же `8bbddb8`, GitHub Release создан не
черновиком.

**Почему мажор, а не минор.** Вопрос владельца был поставлен так: ломающие
изменения заехали только в 3.0.0, в 1.6.0 их не было, — нельзя ли обойтись
без мажора. Нельзя: semver считается против последней **опубликованной**
версии, а `3.0.0` вышла сутками раньше. Проверено не рассуждением, а
исполнением — код в стиле 3.0.0 прогнан против текущего исходника:

- расширение, написанное по документации 3.0.0 (`@override bool
  canFormat(Object? value)`), **компилируется и ведёт себя так же** — Dart
  разрешает расширять тип параметра при переопределении;
- ломается вызов предиката через базовый тип: `Formatter<Money> f;
  f.canFormat(opaque)` — `argument_type_not_assignable`;
- меняется поведение расширения, которое умышленно принимало значения вне
  `T`: раньше оно доходило до `format` и падало `TypeError` внутри
  `FormatExtensionException`, теперь движок его просто не выбирает.

Одного компилируемого сценария, который перестал компилироваться, для
мажора достаточно. Плюс CHANGELOG уже был написан словами «Breaking for
code written against 3.0.0» — минор противоречил бы собственному тексту.

**`3.0.0` ретрактирована** решением владельца, подтверждено публичным API
(`retracted: true`). Ретракт не удаляет версию: она остаётся с бейджем
RETRACTED, новые резолюции её не выбирают, а у кого она в `pubspec.lock` —
продолжают работать. Отменить ретракт можно в течение семи дней, то есть до
2026-08-22; номер 3.0.0 после этого всё равно не переиспользовать —
публикация навсегда.

Риск оценивался до, а не после: по `dependency:format` на pub.dev нашлось
семь сторонних пакетов, и **все они на `^1.x`** — на `^3.0.0` не был завязан
никто, кроме нашего же `format_intl`, который к тому моменту уже допускал оба
мажора.

**Ловушка на будущее: `dart pub retract` не существует.** Среди подкоманд
`dart pub` в 3.13.0 такой нет, хотя документация говорит про ретракт как про
обычную операцию. Делается он из веб-интерфейса pub.dev (вкладка Admin у
пакета), а под ней лежит `PUT
https://pub.dev/api/packages/<пакет>/versions/<версия>/options` с телом
`{"isRetracted": true}`. Эндпоинт не входит в документированный публичный API
(тот объявлен read-only), и OAuth access-токен из `pub-credentials.json` он
не принимает — отвечает `401 MissingAuthentication`; проходит, судя по всему,
OIDC id-токен оттуда же.

**`format_intl` пришлось трогать** — его `format: ^3.0.0` не пустил бы
пользователей на 4.0.0. Ограничение расширено до `>=3.0.0 <5.0.0`, а не
поднято до `^4.0.0`: пакет реализует только `NumberLocale`, которой правка
не касалась, поэтому честно работает на обоих мажорах — и это патч-версия,
а не мажор адаптера.
