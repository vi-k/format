# Восстановление пользовательского example benchmark

## Контекст

Коммит `adabb6d` заменил существующий `example/bin/benchmark.dart`, удалил
адаптеры `SprintfBenchmark` и `Format2Benchmark` и подменил исходную матрицу
тестов release-ориентированным сравнением Legacy/Current. Исходный код можно
полностью восстановить из коммита
`d865cd21056754a2815b23a74f48799756f5ebb9`.

Заменивший его benchmark также сейчас сломан. В Unicode-сценарии семейный emoji
используется как один grapheme fill, но immutable-экземпляр `Format` работает с
режимом по умолчанию `TextUnit.unicodeScalars`. Поэтому сценарий выбрасывает
`InvalidSpecifierException`. Тот же шаблон корректно работает с
`TextUnit.graphemeClusters`.

## Цель

Восстановить исходный пользовательский benchmark и его матрицу сценариев, не
возвращая устаревшую реализацию Format 2 в публичный API пакета. Новый
gate-benchmark нужно сохранить под отдельным понятным entrypoint, чтобы он больше
не подменял пользовательский код.

## Рассмотренные варианты

### 1. Буквально восстановить старый production API

Вернуть `format2()` в `lib/format.dart`, восстановить внешнюю зависимость
`sprintf` и без изменений извлечь исторические example-файлы.

Этот вариант даёт наиболее буквальное восстановление исходников, но возвращает
устаревший публичный API исключительно ради benchmark. Кроме того, release-код
снова начинает зависеть от исторических реализаций. Вариант отклонён.

### 2. Оставить новый benchmark под именем `benchmark.dart`

Добавить исторический benchmark под другим именем и исправить только
Unicode-сценарий в текущем файле.

Так сохраняются текущие пути, но не восстанавливаются принадлежность и прежний
смысл `example/bin/benchmark.dart`. Вариант отклонён.

### 3. Восстановить исходный entrypoint через benchmark-local адаптеры

Восстановить исторический driver, матрицу сценариев, функции вывода и структуру
из трёх движков. Изменить только границы подключения движков:

- текущий Format использует immutable API Format 3: `Format` и `formatWith`;
- Format 2 подключается через локальную для benchmark замороженную реализацию;
- sprintf подключается через замороженную benchmark-реализацию sprintf 7;
- новый gate Legacy/Current переносится в entrypoint с отдельным именем.

Выбран именно этот вариант. Он возвращает пользовательский benchmark, сохраняя
legacy-код вне production и публичных экспортов.

## Архитектура и границы файлов

`example/bin/benchmark.dart` снова становится историческим читаемым driver. Он
обходит восстановленную матрицу brace/printf-тестов, запускает три benchmark-
движка, проверяет каждый результат и печатает время вместе с цветным diff.

Исторические вспомогательные классы восстанавливаются в `example/lib/src/`:

- `format_benchmark.dart` вызывает текущий API Format 3;
- `format2_benchmark.dart` вызывает локальный benchmark-адаптер Format 2;
- `sprintf_benchmark.dart` вызывает замороженный адаптер sprintf 7;
- `my_benchmark_base.dart`, `tests/tests.dart` и `utils/output.dart` сохраняют
  свои исходные роли.

Ни одна legacy-реализация не экспортируется из `lib/format.dart`. Замороженные
исходники импортируются только example/benchmark-кодом. Если прямой
относительный импорт сделает анализ пакета ненадёжным, внутри
`example/lib/src/baselines/` создаётся тонкий адаптер. Он не содержит новой
логики форматирования и фиксирует точное происхождение замороженного исходника.

Заменивший исходный файл gate Legacy/Current сохраняется как
`example/bin/format2_gate_benchmark.dart`. Его вспомогательные файлы изолируются
в `example/lib/src/format2_gate/`. Для Unicode-сценария его `Format` создаётся с
`TextUnit.graphemeClusters`, что соответствует ожидаемой семантике сценария.

Release-harness для нескольких runtime остаётся в `benchmark/runner.dart`. В
рамках этого восстановления он не перемещается и не переименовывается.

## Поток данных

Восстановленный driver выбирает brace- или printf-шаблон для соответствующего
движка, передаёт одинаковые значения, проверяет точное совпадение результата до
принятия замера и при расхождении печатает локализованный diff. Исторические
Format 2 и sprintf доступны только через benchmark-local адаптеры.

Отдельный gate-entrypoint сохраняет текущие сценарии и пороги Legacy/Current. Он
не разделяет изменяемое состояние регистрации с восстановленным benchmark.

## Обработка ошибок

Восстановленный driver по-прежнему изолирует исключения каждого движка. Поэтому
неподдерживаемый случай выводится как ошибка, но не скрывает результаты других
движков. Несовпадения результатов остаются видны как цветной expected/actual
diff.

Gate-entrypoint продолжает немедленно завершаться при несовпадении результата,
поскольку его измерения имеют смысл только после проверки точного output.

## Тестирование и критерии приёмки

Реализация выполняется через цикл RED/GREEN TDD.

Автоматические тесты должны доказать:

1. восстановленный benchmark предоставляет все три движка;
2. типовые integer- и multi-placeholder-сценарии дают ожидаемый результат во
   всех применимых движках;
3. исходный driver сохраняет отдельные brace- и printf-шаблоны;
4. family-emoji fill в gate-benchmark работает в режиме grapheme clusters;
5. ни одна историческая baseline-реализация не импортируется и не экспортируется
   production-кодом.

Проверки из каталога `example/` включают focused-тесты, `dart analyze` и smoke-
запуск обоих entrypoint. После этого один раз запускается полный Dart test suite
репозитория. Существующие изменения `.vscode` не изменяются и не добавляются в
коммит.

## Вне области задачи

- Возврат `format2()` в публичный API Format 3.
- Замена release-harness в `benchmark/runner.dart`.
- Изменение performance-порогов или поведения frozen baseline.
- Переписывание представления или смысла сценариев исторического benchmark.
