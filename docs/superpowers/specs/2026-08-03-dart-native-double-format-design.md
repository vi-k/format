# Dart-native форматирование `double` с совместимым профилем

## Контекст

Пакет использует mini-language из Python для `{...}` и из семейства
`printf` для `%...`. До этого числовой результат также нормативно повторял
Python 3.14 и C++23: точное round-half-even, `inf`/`nan`, собственные пороги
экспоненты и расширенная точность.

Для Dart-разработчика естественнее, чтобы mini-language управлял выбором
представления, шириной и layout, а сами цифры по умолчанию создавались
методами Dart SDK. Точная Python/C++-совместимость остаётся доступной как
явная настройка и не должна терять достигнутую производительность.

## Цели

- сохранить синтаксис `{...}` и `%...`;
- сделать поведение `double` из Dart SDK профилем по умолчанию;
- оставить явный совместимый профиль: Python для brace и C++ для `printf`;
- отдельно настраивать длинное или короткое написание специальных значений;
- не менять единые правила для остальных типов без аналога в Dart SDK;
- сохранить быстрый compatible-путь обычного `f`;
- дать пользователю наглядный цветной benchmark обоих режимов.

## Вне области работ

- изменение грамматики полей и спецификаций;
- добавление профильного флага внутрь шаблона;
- отдельные профили для `int`, `String`, `List`, `Map` и `Set`;
- изменение custom formatter, lookup, locale и text-unit API;
- полная замена parser или layout-кода.

## Публичный API

Добавляются два enum:

```dart
enum DoubleFormatMode {
  dartSdk,
  compatible,
}

enum DoubleSpecialValueSpelling {
  dartSdk,
  short,
}
```

`Format` получает неизменяемые параметры:

```dart
Format({
  this.doubleFormatMode = DoubleFormatMode.dartSdk,
  this.doubleSpecialValueSpelling =
      DoubleSpecialValueSpelling.dartSdk,
  // существующие параметры
});
```

`defaultFormat`, top-level `format()` и `sprintf()` используют Dart-профиль.
Для совместимого результата разработчик создаёт и переиспользует экземпляр:

```dart
final compatibleFormat = Format(
  doubleFormatMode: DoubleFormatMode.compatible,
);
```

Отдельные классы, named constructors и переключатели внутри шаблона не
добавляются.

## Архитектура

Парсеры brace и `printf`, разрешение значений и общий layout остаются
едиными. Профиль выбирает только генератор исходного ASCII-представления
`double`:

```text
template
   ↓
общий parser и resolver
   ↓
double conversion
   ├─ dartSdk     → методы double из Dart SDK
   └─ compatible  → текущие Binary64/BigInt и fast path
   ↓
общие sign, z, #, grouping, locale, width и alignment
```

`Binary64` не создаётся в Dart-профиле. Compatible-профиль сохраняет ленивое
создание `Binary64`, быстрый ASCII-разбор `.0f`…`.20f`, кэшированные
`_FormatSpec` и безопасный `toStringAsFixed` fast path. Точное округление
через `BigInt` вызывается только на существующих сложных границах.

## Dart SDK профиль

Генерация конечного тела следует этой таблице:

| Тип | Без precision | С precision |
| --- | --- | --- |
| пустой | `value.toString()` | правила `g` |
| `f`/`F` | `toStringAsFixed(6)` | `toStringAsFixed(N)` |
| `e`/`E` | `toStringAsExponential()` | `toStringAsExponential(N)` |
| `g`/`G` | `value.toString()` | `toStringAsPrecision(N)` |
| `n` | `value.toString()` + locale | `toStringAsPrecision(N)` + locale |
| `%` | умножение на 100 и fixed с 6 знаками | fixed с `N` знаками |

Для `f` и `%` сохраняется default precision `6`, потому что
`toStringAsFixed` требует обязательный аргумент. Прочие результаты принимают
правила Dart SDK, в том числе:

- `2.5` с `.0f` округляется в `3`;
- `f` может перейти в экспоненциальную запись при модуле от `1e21`;
- `e` без precision использует кратчайшую запись вроде `1e+0`;
- `g` с precision сохраняет указанное число значащих цифр и конечные нули;
- `f`, `e` и `%` принимают precision `0…20`;
- `g` и `n` принимают precision `1…21`;
- precision вне диапазона превращается в существующую типизированную
  `InvalidSpecifierException` до вызова SDK, поэтому `RangeError` наружу не
  выходит.

Uppercase-типы переводят обычный показатель `e` в `E`. Написание специальных
значений определяется отдельно.

## Compatible-профиль

Compatible-профиль сохраняет текущий числовой контракт и результаты:

- brace следует Python для `f`, `e`, `g`, `%`, пустого типа и `n`;
- `printf` следует текущему детерминированному C++-совместимому подмножеству;
- округление остаётся round-half-even;
- сохраняются расширенная precision и точный `Binary64` fallback;
- сохраняются текущие exponent spelling, пороги и alternate form;
- обычные значения продолжают использовать существующий быстрый путь.

Изменение default-профиля не разрешает удалять или замедлять compatible-код.

## Специальные значения и регистр

В Dart-профиле значение по умолчанию:

```text
NaN
Infinity
-Infinity
```

`DoubleSpecialValueSpelling.short` переключает основу на:

```text
nan
inf
-inf
```

Compatible-профиль всегда использует короткую основу, независимо от значения
`doubleSpecialValueSpelling`. Это намеренный приоритет профиля, а не ошибка
конфигурации. Uppercase-типы сохраняют регистр: короткие `nan`/`inf`
становятся `NAN`/`INF`. Dart-написания `NaN`/`Infinity` не изменяются.

## `!r`, `!a` и контейнеры

Структура диагностического представления остаётся общей для обоих режимов:
кавычки и escaping строк, порядок коллекций, custom `Representation` и защита
от циклов не меняются.

Представление каждого вложенного `double` использует текущий
`doubleFormatMode` и эффективное написание специальных значений. Поэтому
режим действует и на число внутри `List`, `Map` или `Set`, а `!a` после этого
экранирует все не-ASCII scalars.

Контейнеры не получают отдельного compatibility-параметра:

| Значение | Результат `!r` во всех режимах |
| --- | --- |
| пустой `List` | `[]` |
| пустой `Map` | `{}` |
| пустой `Set` | `{}` |
| непустой `List` | `[1, 'x']` |
| непустой `Map` | `{'x': 1}` |
| непустой `Set` | `{'x', 1}` |

Совпадающее представление пустых `Map` и `Set` намеренно повторяет привычный
Dart `toString()` и документируется как неоднозначное. Результат `!r` не
предназначен для восстановления runtime-типа контейнера.

## Locale и общий layout

После получения тела оба профиля используют один код для:

- знака и нормализации отрицательного нуля `z`;
- alternate form `#`;
- целой и дробной группировки;
- `NumberLocale` и `format_intl`;
- fill, width и alignment;
- percent suffix.

Тип `n` остаётся расширением пакета: сначала создаётся тело по правилам `g`
выбранного профиля, затем локализуются знаки, цифры и разделители.

## Пользовательский benchmark

Добавляется `example/bin/float_modes_benchmark.dart`, запускаемый командой:

```sh
cd example
dart run bin/float_modes_benchmark.dart
```

Для каждого brace- и printf-сценария он печатает:

- шаблон и исходное значение;
- фактический результат Dart SDK профиля;
- фактический результат compatible-профиля;
- медианное время каждого режима в `µs/op`;
- процентную разницу и более быстрый режим;
- отдельное предупреждение, если результаты намеренно различаются.

Матрица включает обычный и большой `f`, half-tie `2.5`, `e`, `g`, `NaN` и
`Infinity`. Оба режима прогреваются, порядок измерений чередуется, берётся
медиана нескольких серий, а checksum не позволяет удалить вызовы.

Вывод использует существующие `ansi_escape_codes`,
`ansi.runZonedPrinter`, `defaultFg` и helpers из
`example/lib/src/utils/output.dart`. Собственная палитра или сырые ANSI-коды
не вводятся. В `.vscode/launch.json` добавляется отдельный запуск и включение
в compound для всех benchmark.

## Автоматические тесты и performance gates

Тесты Dart-профиля сравнивают публичный API непосредственно с методами Dart
SDK. Проверяются оба диалекта, отсутствие и наличие precision, границы
диапазонов, half-ties, `-0.0`, `1e21`, `NaN`, `Infinity`, регистр, настройка
коротких специальных значений, `n`, `%` и вложенные `double` в `!r`/`!a`.

Существующие Python и C++ fixtures переводятся на явно настроенный compatible
`Format`. Их результаты не меняются, кроме согласованного общего результата
`{}` для пустого `Set`, который документируется как Dart-ориентированное
отклонение вне числового профиля.

Benchmark matrix содержит отдельные scenario id для Dart SDK и compatible.
Compatible-сценарии обычного и большого `f` остаются ключевыми и проходят два
gateable JIT- и два AOT-отчёта с отношением к замороженному Format 2 не выше
`1.05`. Отдельные correctness/performance проверки охватывают JavaScript.

## Документация и миграция

README и CHANGELOG описывают пакет как Dart formatting API со знакомыми
Python/C-style mini-languages, а не как безусловно Python-compatible пакет.
В документации приводятся оба режима, различия округления, пределы precision,
специальные значения и неоднозначность пустых `Map`/`Set` в `!r`.

Переход меняет результат top-level API, потому что default становится
Dart SDK. Пользователь, которому нужны прежние результаты, должен создать
`Format(doubleFormatMode: DoubleFormatMode.compatible)` и использовать его
методы `format`, `formatWith`, `sprintf` и `vsprintf`.
