# Дизайн: покрытие типов и ускорение сравнительного бенчмарка

Дата: 2026-08-04
Статус: одобрен пользователем (в чате)

## Цель

Расширить сравнительный бенчмарк (`example/bin/benchmark.dart`) на все
распространённые сценарии форматирования, включая fill/align, убрать
избыточные строки и сократить время полного прогона с ~2.8 минут до
~30–45 секунд, сохранив режим точных измерений.

## Ограничения (решения пользователя)

- Все четыре раннера остаются на каждом сценарии, где применимы:
  `sprintf 7.0 → sprintf`, `format 2.0 → format`, `format 3.0 → format`,
  `format 3.0 → sprintf`.
- `benchmark_harness` остаётся основой измерений.
- Быстрый прогон — дефолт; точный — по флагу `--full`.

## Проверенные факты

- `BenchmarkBase.measure()` в benchmark_harness 2.3.1 — переопределяемый
  метод экземпляра; `BenchmarkBase.measureFor` — публичный статический.
  Длительности (прогрев 100 мс + замер 2000 мс) можно менять, оставаясь
  на harness.
- printf-движок format 3.0 поддерживает `c s d i u o x X a A e E f F g G %`;
  `%b` не поддерживается — двоичный тип идёт только через brace.
- legacy format 2.0 поддерживает `b` и fill/align.

## Матрица сценариев

«—» в колонке sprintf означает: sprintf-шаблона нет, оба printf-раннера
(`sprintf 7.0`, `format 3.0 → sprintf`) пропускаются.

Удаляются: `{:10d} ` ×10 (дублирует идею множественного шаблона) и
избыточные значения существующих строк (третьи значения там, где хватает
одного-двух).

Ожидаемые строки результата фиксируются в матрице (как сейчас) и
вычисляются при реализации. Значения подобраны так, чтобы все
участвующие раннеры давали одинаковый результат; если конкретное
значение вскрывает расхождение раннеров (как известный баг sprintf 7.0
с минимальным int), значение заменяется, а не маскируется.

Известное исключение сохраняется: минимальный int в строке 1 больше не
используется (двойной минус sprintf 7.0) — вместо пары max/min остаётся
0 и максимальный int.

## Модель данных

Строка матрицы — класс (record не может нести необязательное поле
с значением по умолчанию):

```dart
final class BenchmarkScenario {
  final String? brace;
  final String? sprintf;
  final bool skipLegacy; // default false
  final List<(List<Object?>, String)> cases;
}
```

- Раннер участвует, только если его шаблон задан (`brace` — для
  format 2.0/3.0 format, `sprintf` — для sprintf 7.0 и format 3.0
  sprintf).
- Для точечных несовместимостей legacy format 2.0 (если вскроются
  эмпирически, например Unicode fill) — необязательное поле
  `skipLegacy: bool` со значением по умолчанию `false`. Пропуск
  отображается как «—», а не как ERROR.

## Запуск и тайминг

Логика прогона переносится из `bin/benchmark.dart` в
`example/lib/src/comparison_benchmark.dart` в функцию
`runComparisonBenchmark({List<String> args, BenchmarkLineWriter? writeLine,
BenchmarkDurations? durations})` — по образцу
`runDoubleModesBenchmark`. `bin/benchmark.dart` остаётся тонкой обёрткой
(ANSI-зона + вызов функции).

`MyBenchmarkBase` получает длительности измерения:

```dart
final class BenchmarkDurations {
  final int warmupMillis;   // quick: 50,  full: 100
  final int measureMillis;  // quick: 180, full: 2000
}
```

`measure()` переопределяется: `setup(); measureFor(warmup, warmupMillis);
result = measureFor(exercise, measureMillis); teardown();` — тот же
harness, другие минимумы.

CLI: без флагов — quick; `--full` — точный режим. Другие аргументы —
ошибка с подсказкой.

Оценка: 30 строк значений; полные строки — 4 раннера, brace-only — 2,
итого ~106 измерений; с константами quick 50/180 ms — 44.2 с;
`--full` ≈ 3.7 мин.

## Вывод

Формат сохраняется (заголовки, `OK`/`ERROR` с диффом). Дополнительно:

- пропущенный раннер печатает `—` вместо замера;
- в конце — суммарное время прогона и активный режим (quick/full).

## Тесты

`example/test/restored_benchmark_test.dart` (и при необходимости новый
файл) по TDD:

- пины структуры матрицы: количество строк, наличие групп (целые,
  doubles, строки, ×10), отсутствие удалённых строк;
- null-sprintf строка не запускает printf-раннеры (через
  `runComparisonBenchmark` с injected `writeLine` и минимальными
  длительностями — в выводе «—»);
- `--full`/дефолт переключают `BenchmarkDurations` (ассерт на
  конфигурацию, не на время);
- неизвестный аргумент — ошибка.

Timing-ассертов в unit-тестах нет (правило проекта).

## Вне охвата

- `double_modes_benchmark` и `format2_gate` не меняются.
- Инфраструктура gates в корневом `test/` не меняется.
- Производственный код `lib/` не меняется.

## Проверка результата

- `dart test` в `example/` и корне — зелёные.
- `dart analyze` — без новых замечаний.
- Прогон `dart run bin/benchmark.dart`: все строки OK (кроме «—»),
  время ~30–45 с.
- Переключение `--full` проверено тестом конфигурации (полный прогон
  вручную не обязателен).
