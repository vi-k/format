# Дизайн: компиляция шаблонов в IR с прямой записью в буфер

Дата: 2026-08-04
Статус: одобрен пользователем (в чате)

## Цель

Убрать промежуточные строки с горячего пути форматирования: сегодня
каждое поле рождает отдельную строку (`toString`/`toRadixString`
цифр, конкатенация sign+prefix+digits, `fill * padding`), которая
затем копируется в общий `StringBuffer`. Вместо этого кэшированный
AST один раз компилируется в последовательность специализированных
op'ов, пишущих напрямую в общий буфер code units. Ориентир: ключевые
горячие сценарии (`{:10d}` 0.27, `{:s}` 0.08, `{:<10s}` 0.17,
`%s` 0.11, `%10d` 0.29 мкс) должны заметно ускориться.

## Решения пользователя

- Охват v1 — горячее ядро обоих диалектов: literal, int
  (`d/x/X/o/b` и printf `d/i/u/o/x/X` без locale/grouping), text
  (`s`, пустая спека при строке, printf `%s`). Всё остальное —
  fallback-op через существующий строковый путь.
- Критерий GREEN: статистически устойчивое ускорение ключевых
  горячих сценариев без регрессий на остальных (включая cold);
  жёсткая планка (×N) заранее не фиксируется. Нет GREEN — нет
  коммита.
- Платформы: оптимизируем под VM (JIT/AOT); на JS гарантируется
  корректность (node-тесты), бенчмарк смотрим информационно.
  Драматичная деградация JS — повод пересмотреть sink.
- Архитектура: sealed op-классы + интерпретатор (не closure-IR и не
  писатели на узлах AST) — ради интроспекции через debug-seam,
  мономорфного диспатча и задела под double-op'ы в следующей
  итерации.
- Старые процессоры в этой итерации не удаляются — остаются под
  debug-seam для дифференциального теста; удаление — отдельная
  задача после стабилизации.

## Ключевые факты (проверены в сессии)

- Оба процессора собирают вывод из per-field строк; внутри числовых
  путей 3–5 промежуточных строк на поле (`number_format.dart`:
  `applyNumericWidth`, `_asciiSign`, `groupDigits`;
  `value_formatter.dart`: `applyFieldWidth`).
- Горячие op'ы не зависят от состояния `Format`, кроме `textUnit`:
  locale (`n`), custom formatters и `doubleFormatMode` встречаются
  только на fallback-путях v1. Значит, программе достаточно двух
  слотов по `TextUnit` на кэшированном шаблоне — тот же паттерн, что
  у мемоизации `_FormatSpec` в `_FieldNode`.
- printf-аргументы (значение, `*`-width, `*`-precision) потребляются
  строго последовательно, порядок известен на этапе парсинга —
  индексы аргументов раздаются статически при компиляции, курсор
  аргументов уходит с горячего пути. Автонумерация `{}` в brace
  статична так же.
- Тип значения известен только в рантайме: специализация op'а
  выбирается по шаблону, но op обязан ветвиться по фактическому типу
  (`int`/`BigInt`/прочее) и в точности воспроизводить сегодняшние
  исключения.
- `String.fromCharCodes(Uint16List)` — одна финальная копия; запись
  code units безопасна для суррогатных пар и графем (единицы UTF-16
  сохраняются как есть, `TextUnit` влияет только на подсчёт
  длины/truncate).

## Архитектура

### `_CharSink` (`lib/src/char_sink.dart`, part of engine)

Растущий `Uint16List` + длина, удвоение при переполнении, стартовая
ёмкость — сумма длин литералов + 16 на поле. Операции:

- `writeString(String)` — `setRange` из `codeUnits`;
- `writeCharCode(int)`;
- `fill(int charCode, int count)` — `fillRange` (паддинг, нули
  printf-precision);
- запись целых напрямую: количество цифр лесенкой сравнений, цифры
  делением задом наперёд в заранее отведённый диапазон. minInt
  безопасен: работаем с отрицательной величиной,
  `-(v.remainder(radix))`. Radix 2/8/16 — сдвиги и маски;
- `toString()` — `String.fromCharCodes(buffer, 0, length)`.

Один sink на вызов `format()`, без пула в v1 (fallback может
реентерабельно позвать `format()` из custom formatter; пул — только
после A/B-замера, вне охвата).

### IR (`lib/src/template_ir.dart`, part of engine)

Sealed-иерархия `_Op` с методом `write(sink, positional, named,
engine)`; программа — `List<_Op>`; интерпретатор — цикл с
мономорфным вызовом. Компилятор обходит кэшированный AST и
классифицирует каждый узел:

| Op | Покрывает | Техника |
|---|---|---|
| `_LiteralOp` | текст между полями; `%%` вливается в соседний литерал | `setRange` из заранее извлечённого `Uint16List` |
| `_IntOp` | brace `d/x/X/o/b`, printf `d/i/u/o/x/X` без locale/grouping; статические и `*`-опции | знак/префикс `writeCharCode`, паддинг `fill`, цифры делением/сдвигами; align `<`/`>`/`^`/`=` запечён |
| `_TextOp` | brace `s` и пустая спека при `String`, printf `%s` | truncate `textUnit.take`, паддинг `fill`, тело `setRange` |
| `_DynamicValueOp` | brace `{}` — тип значения только в рантайме | ветвление: `String`→текст, `int`→цифры, `bool`/`null`→`toString`; прочее → медленная ветка (formatters и т.д.), зеркалит диспатч `formatParsedValue` |
| `_FallbackOp` | double, `n`/locale, grouping, `c`, conversion, accesses, вложенные `{:{}d}`, невалидные статические спеки | существующий строковый путь, результат `writeString` |

Компиляция тотальна и не бросает: всё непокрытое или ошибочное
превращается в `_FallbackOp`, который на каждый вызов воспроизводит
сегодняшнее поведение бит-в-бит — и строки, и исключения с теми же
контекстами (ошибка парсинга статической спеки по-прежнему кидается
на каждом вызове и не мемоизируется).

Рантайм-типы: `_IntOp` — `int` прямая запись; `BigInt` — полугорячая
ветка (`toRadixString` величины + прямой паддинг); прочее — то же
исключение, что сегодня; printf `u` при отрицательном значении —
сегодняшний `UnsupportedFormatValueException`. `_TextOp` в brace при
не-`String` уходит в fallback-ветку с идентичной ошибкой; printf
`%s` зовёт `value.toString()` у любого типа (эта строка аллоцируется
и сегодня — экономия на truncate/паддинге/копиях) с сегодняшним
оборачиванием ошибок `toString`.

printf-динамика (`*`) остаётся горячей: width/precision читаются по
статическим индексам, валидация как сейчас (`_maximumSafeOption`,
отрицательная ширина → left + abs, отрицательная precision → null),
дальше тот же прямой писатель. `printf.dynamic.hot.10` — ключевой
сценарий, обязан ускориться.

Ошибки: op хранит ссылку на узел AST; `FormatExceptionContext`
строится лениво только на пути ошибки, поля те же (offset, fragment,
specifier, conversion, argumentIndex). Порядок исключений
сохраняется: op'ы исполняются в порядке полей, индексы аргументов —
в сегодняшнем порядке потребления (width → precision → значение).

### Кэширование программы

Кэш AST не меняется (`template_cache.dart`, ёмкость 512, полная
очистка). `_BraceTemplate`/`_PrintfTemplate` получают по два ленивых
слота программы (`TextUnit.unicodeScalars`/`graphemeClusters`);
компиляция при первом `format()` с данным `TextUnit`.
`debugClearTemplateCaches` работает без изменений: программы живут
на кэшируемых объектах и умирают вместе с ними.

### Переходная стратегия

`_BraceProcessor.format()`/`_PrintfProcessor.format()` остаются в
кодовой базе и доступны через seam `debugFormatWithoutIr(...)`
(экспорт через `package:format/src/engine.dart`, как остальные
seam'ы). Публичный путь переключается на IR. Удаление старых
процессоров — вне этой итерации.

## Бенчмарк и performance-гейт

### Отдельный A/B-прогон (по образцу `double_modes_benchmark.dart`)

Новая пара файлов: `example/bin/template_ir_benchmark.dart` (тонкая
обёртка с `ansi.runZonedPrinter`) и
`example/lib/src/template_ir_benchmark.dart`
(`runTemplateIrBenchmark({writeLine, warmupOperations, operations,
samples, equivalenceThresholdPercent})`, testable через `writeLine`).
Запуск после работы показывает результат сразу:

- сценарии — ключевые горячие формы (`{:10d}`, `{:s}`, `{:<10s}`,
  `{}`, `%s`, `%10d`, `%0*d` с динамикой) плюс пара
  fallback-контрольных (`{:.2f}`, `{:é^10s}` на графемах) — они
  обязаны показать EQUAL, а не регрессию;
- A/B: публичный путь (IR) против старого строкового пути через
  seam'ы `debugFormatBraceWithoutIr`/`debugFormatPrintfWithoutIr`
  (импорт `package:format/src/engine.dart`);
- методика как в double_modes: сверка результатов A и B перед
  замером, warmup, чередование сторон по сэмплам, медиана, µs/op на
  сценарий и вердикт `IR FASTER: N%` / `PERFORMANCE EQUAL` /
  `RESULTS DIFFER`;
- интеграционный тест по образцу существующих: прогон с малыми
  операциями через `writeLine`, ноль `RESULTS DIFFER`.

Это ещё одна причина держать старые процессоры под seam'ом всю
итерацию: они — baseline этого прогона.

### Гейт на общей матрице

- RED: перед реализацией зафиксировать текущие числа
  `example/bin/benchmark.dart` quick на тихой машине (проверка
  `sysctl -n vm.loadavg`).
- GREEN: устойчивое ускорение ключевых горячих сценариев (`{:10d}`,
  `{:s}`, `{:<10s}`, `%s`, `%10d`, `printf.dynamic.hot.10`);
  отсутствие регрессий на остальных сценариях в пределах
  существующего equivalence threshold бенчмарка.
- Cold: компиляция ленивая, cold-сценарии её увидят. Бюджет —
  cold-дельта в пределах порога шума; если дороже — эскалация к
  компиляции со второго вызова (счётчик на шаблоне), вне v1.
- JS-бенчмарк — информационно; полный quick-прогон ≤ 60 с.

## Тесты (TDD)

Debug-seam'ы (не экспортируются из `format.dart`, импорт только
через `package:format/src/engine.dart` — ловушка двойной
библиотеки):

```dart
List<String> debugCompiledProgramDescription(String template,
    {required bool printf, required TextUnit textUnit});
// Старый путь, для дифф-теста:
String debugFormatBraceWithoutIr(String template, Format engine,
    {List<Object?> positional, Map<String, Object?> named});
String debugFormatPrintfWithoutIr(String template, Format engine,
    List<Object?> values);
```

Порядок: sink с юнит-тестами → компилятор с seam-тестами формы
(горячие шаблоны компилируются в горячие op'ы: `['literal',
'int:d:w10']`; экзотика — в `fallback`) → op'ы по одному с
дифф-тестами → переключение `format()` на IR → полный прогон.

Дифференциальный тест: табличная матрица шаблонов (горячие формы +
границы: minInt через выражение без литерала в кросс-платформенных
файлах, BigInt, пустые строки, суррогаты/графемы на обоих
`TextUnit`, ширина больше/меньше контента, precision 0, `*`-опции,
ошибочные значения) × значений; сравниваются строки и типы
исключений с полями контекста между IR и `debugFormatWithoutIr`.
Тесты кэша/программы зовут `debugClearTemplateCaches` в `setUp`.

Timing-ассертов в unit-тестах нет; performance — только через
бенчмарк.

## Вне охвата

- Прямая запись double (`f/e/g/a`) — следующая итерация поверх
  op-иерархии.
- Grouping и locale в горячих op'ах; `c`; conversion; accesses.
- Пул sink'ов; гибридный sink для JS; компиляция со второго вызова.
- Удаление старых процессоров.
- Публичный API управления кэшем/компиляцией.

## Проверка результата

- `dart test` в корне и `example/` — зелёные; node-прогон — зелёный
  (IR корректен на JS).
- `dart analyze lib test example` — без новых замечаний.
- Seam-тесты пиннят состав программ; дифф-тест зелёный на обоих
  `TextUnit`.
- `dart run example/bin/template_ir_benchmark.dart` — итоговый
  A/B-отчёт: горячие сценарии `IR FASTER`, fallback-контрольные не
  хуже EQUAL, ни одного `RESULTS DIFFER`.
- Бенчмарк: GREEN по критерию выше, единственный ERROR — намеренный
  sprintf 7.0 на минимальном int.
